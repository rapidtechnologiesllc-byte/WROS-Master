## Why — Business Rationale

- A weekend entry, a 14-hour day, or hours logged against a project that closed last month are usually innocent mistakes — but they're also exactly the kind of thing a manager should see before approving, not discover during an audit months later. This is a lightweight quality check on the data entering the billing pipeline, not a policing tool.

## What — Scope

- Automated flagging of four timesheet anomaly patterns — weekend entries, days over 12 hours, entries against already-completed projects, and duplicate entries — surfaced to the approving manager before they approve, not after.

## Before — Prerequisites

- HRMS-0905 Timesheet base must be live and producing entries to check.

## Implementation Steps

## Step 1: Build the weekend-entry check

- Flag any entry with a work_date falling on Saturday or Sunday, unless the project is explicitly configured to allow weekend billing (client-specific exception).

## Step 2: Build the over-12-hours check

- Flag any single day's logged hours exceeding 12.

## Step 3: Build the completed-project check

- Flag entries logged against a project with status=COMPLETED.

## Step 4: Build the duplicate-entry check

- Flag two entries for the same employee, same project, same date.

## Step 5: Surface flags to the approving manager

- Flags appear inline on the approval screen before the manager approves, not as a separate post-approval report.

## Business Rules

## BR: BR-0910-01 — Flags are advisory, they do not block approval

- A weekend entry might be entirely legitimate (a genuine emergency deployment) — this story surfaces the pattern for a manager's informed judgment, it does not prevent approval outright.

- Field: Anomaly flags are display-only annotations, no hard block exists on the approval action

## BR: BR-0910-02 — Weekend flagging respects per-project weekend-billing configuration

- Some client engagements legitimately involve weekend work — the check should not generate noise for those, or managers will start ignoring all flags.

- Field: Weekend check reads project.allow_weekend_billing before flagging

## Acceptance Criteria

- AC-1: A weekend entry on a project without weekend-billing configured is flagged; the same entry on a project with it configured is not.

- AC-2: Anomaly flags never block the approval action itself, only annotate it.

- AC-3: A duplicate entry (same employee, project, date) is correctly flagged.

## Not In Scope

- No automatic rejection of anomalous entries — flags are advisory only, per BR-0910-01.

- No AI-based fraud scoring — these are simple structural checks, not a behavioral risk model.
