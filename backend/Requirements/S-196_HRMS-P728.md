## Why — Business Rationale

- A client's first question logging into the portal is always some version of 'how's my engagement doing right now' — active headcount, anything pending their attention, anything at risk. A single real-time overview answers that in one glance instead of a client digging through separate screens.

## What — Scope

- A real-time client dashboard: active consultants, timesheets pending their approval, open submissions, milestone summary, and open RFPs — mobile-responsive, and deliberately scoped to contain zero financial data, zero bench visibility, and zero other client's data.

## Before — Prerequisites

- HRMS-P703 must expose client-scoped read access to allocations, timesheets, submissions, and RFP data.

## Implementation Steps

## Step 1: Build the dashboard widgets

- Active consultants count, timesheets pending count with direct link into S-182, open submissions count, milestone summary, open RFP count with link into S-190.

## Step 2: Enforce the scope boundary

- No financial/billing figures, no bench pool visibility, no data belonging to any other client — every widget query is scoped to client_id from session, same discipline as HRMS-0109.

## Step 3: Build mobile responsiveness

- Widget grid collapses to a single column below tablet breakpoint.

## Business Rules

## BR: BR-0728-01 — Zero financial, bench, or cross-client data on this dashboard

- This is an explicit, deliberate scope boundary — a client-facing delivery dashboard is not a window into BlitzenX's internal margin, bench composition, or another client's engagement.

- Field: Every dashboard query is scoped to client_id and explicitly excludes financial/bench tables
