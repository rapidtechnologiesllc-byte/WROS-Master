## Why — Business Rationale

- R-09 already mandates that every monetary value is stored in USD cents with no mixed-currency storage — that rule protects the data. This story protects the humans reading it: a BU Head in London and a Director in Mumbai both need to see a billing rate in their own currency and their own date format without either of them doing mental conversion, and without ever risking a second currency actually being written to the database.

## What — Scope

- Per-tenant/per-BU locale settings (timezone, date format, display currency) plus the single convertFromUSD() display function every screen uses to render a stored USD-cents value in the viewer's preferred currency — display-only, storage is untouched.

## Before — Prerequisites

- HRMS-0115 System Configuration must be live — locale settings are stored as config entries.

## Implementation Steps

## Step 1: Extend system_config with locale keys

- timezone, date_format, display_currency (USD/GBP/EUR/INR/CAD) per BU per Section 7.1 data rules.

## Step 2: Build convertFromUSD()

- Single shared function: takes USD cents + target currency, returns formatted display string using a maintained exchange-rate table.

- This is the ONLY sanctioned path from stored value to displayed value — no story formats currency independently.

## Step 3: Build the exchange rate refresh job

- Daily job pulls current rates from a rate provider, stores a dated snapshot — historical figures always display using the rate current at time of original transaction, not today's rate, to avoid retroactively changing historical reports.

## Step 4: Wire date/time formatting

- All displayed timestamps render in the viewing user's configured timezone and date format, converted from the UTC-stored value.

## Business Rules

BR: BR-0121-01 — Storage is always USD cents; display currency never affects what's written to the database

- Directly enforces R-09 — convertFromUSD() is a read-time, display-only transformation with no write path back to storage.

- Field: convertFromUSD() has no corresponding convertToUSD-and-store function — conversion is one-directional, display-only

BR: BR-0121-02 — Historical monetary displays use the exchange rate current at transaction time, not today's rate

- Prevents historical financial reports from silently changing value every time someone views them on a different day.

- Field: exchange_rate_snapshots is dated; display joins to the snapshot matching the original transaction's date, not the latest

## Acceptance Criteria

- AC-1: A monetary value stored as USD cents displays correctly converted in each of the 5 supported currencies without ever altering the stored value.

- AC-2: A historical transaction viewed today displays using the exchange rate from its original transaction date, not the current rate.

- AC-3: A stale exchange-rate feed (3+ days old) triggers an alert while continuing to serve the last known snapshot rather than failing displays.

- AC-4: Timestamps render in the viewing BU's configured timezone and date format.

## Not In Scope

- No user-level (as opposed to BU-level) currency override in this story — currency display is BU-wide for consistency in shared reports.

- No live/real-time exchange rate ticking — daily snapshot only, this is a staffing platform, not a trading system.
