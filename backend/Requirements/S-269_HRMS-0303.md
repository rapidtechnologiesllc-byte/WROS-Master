## Why — Business Rationale

- Once the BU has a target and a role mapping, the system should auto-generate a workforce demand plan — a structured set of role demands with quantities, timelines, and sourcing strategies. This eliminates the manual spreadsheet planning that currently happens outside WROS and ensures every demand is traceable to a revenue commitment.

## What — Scope

- Build: (1) Demand plan generation from target + role mapping. (2) Bench-first deduction — check bench before generating external demand. (3) Demand plan approval workflow. (4) Demand plan storage as a versioned document.

## Before — Prerequisites

- HRMS-0301 targets. HRMS-0302 role mapping. HRMS-0503 bench pool. HRMS-0506 staffing eligibility.

## Implementation Steps

## Step 1: Create workforce_demand_plans and workforce_demand_plan_items tables

- CREATE TABLE workforce_demand_plans: id UUID PK, tenant_id UUID, bu_id UUID, fiscal_year INTEGER, target_period VARCHAR(10), status ENUM('DRAFT','PENDING_APPROVAL','APPROVED','ACTIVE','CLOSED'), total_heads_required INTEGER, total_heads_from_bench INTEGER, total_heads_external INTEGER, created_by UUID, approved_by UUID nullable, approved_at TIMESTAMP nullable, created_at TIMESTAMP

- CREATE TABLE workforce_demand_plan_items: id UUID PK, plan_id UUID FK→workforce_demand_plans, role_type VARCHAR(200), delivery_engine ENUM('SPECIALITY','CORE'), heads_required INTEGER, heads_from_bench INTEGER, heads_external INTEGER, target_start_month DATE, sourcing_strategy ENUM('BENCH_REDEPLOY','EXTERNAL_HIRE','HTD','SUBVENDOR'), urgency ENUM('IMMEDIATE','HIGH','NORMAL')

## Step 2: Build DemandPlanGenerator service

- DemandPlanGenerator.generate(bu_id, fiscal_year, target_period): (1) Fetch target from bu_revenue_targets. (2) Run HeadcountCalculator → get heads_required per role. (3) For each role: query bench pool for available employees with matching skills. Deduct bench-available heads from external demand. (4) Net external demand = heads_required - heads_from_bench. (5) For each external demand item: assign sourcing_strategy based on role type (HTD-eligible roles → HTD, Guidewire laterals → EXTERNAL_HIRE).

- Create workforce_demand_plan record with status=DRAFT. Insert one workforce_demand_plan_items record per role type.

## Step 3: Build plan approval workflow

- PATCH /api/workforce-planning/plans/{id}/submit: changes status to PENDING_APPROVAL. Notifies BU Head.

- PATCH /api/workforce-planning/plans/{id}/approve: Auth BU Head only. Sets status=APPROVED, approved_by, approved_at. Triggers HRMS-0307 sourcing workflow and HRMS-0309 job req auto-creation.

- PATCH /api/workforce-planning/plans/{id}/reject: body { reason }. Returns to DRAFT with rejection notes.

## Business Rules

## BR: Bench-First Deduction Is Mandatory Before Generating External Demand

- DemandPlanGenerator MUST check bench availability before creating external demand items. A role with bench-available employees of matching skills cannot be planned as external hire without BU Head explicit override with logged justification. This enforces the bench-first policy at the planning level, not just at execution.

- Field: Bench deduction required — no external demand if bench available

## BR: Approved Plan Triggers Sourcing Automatically

- Plan approval is the gate that starts work. On APPROVED status: system automatically triggers sourcing workflow (HRMS-0307) and creates job requisitions (HRMS-0309) for all external demand items. No separate manual trigger needed.

- Field: Approval = automatic sourcing trigger

## BR: One Active Plan Per BU Per Period

- A BU cannot have two APPROVED plans for the same fiscal_year + target_period. Attempting to approve a second plan for the same period: system returns error and requires the existing plan to be CLOSED first.

- Field: One active plan per BU per period
