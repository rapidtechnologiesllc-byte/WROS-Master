## Why — Business Rationale

- When Core and Speciality both need the same employee simultaneously, there is one rule and it is not negotiable: Core wins. This story builds the deterministic engine that detects the conflict, executes the reallocation same-day, notifies the Speciality RM, and logs the transfer. No debate. No committee. The engine decides.

## What — Scope

- Build CorePullEngine: detects simultaneous Core and Speciality demand for the same Core-Certified employee. Executes Core allocation. Logs transfer. Notifies Speciality RM. Publishes MEDIUM risk event to Orchestration Router. BU Head override path exists but requires explicit logged justification.

## Before — Prerequisites

- HRMS-0512 engine model. HRMS-0507 employee_allocations. HRMS-1101 Orchestration Router live.

## Implementation Steps

## Step 1: Build CorePullEngine.detect()

- Runs every 30 minutes and on every new demand creation/allocation attempt.

- Detection: SELECT employees WHERE core_certified=TRUE AND id IN (SELECT employee_id FROM pending_allocations WHERE delivery_engine=CORE) AND id IN (SELECT employee_id FROM active_allocations WHERE delivery_engine=SPECIALITY).

- On match: creates core_pull_events record: employee_id, core_demand_id, speciality_allocation_id, detected_at, status=PENDING.

## Step 2: Build CorePullEngine.execute()

- On detection: publish agent.action.intent to HRMS-1101 Orchestration Router with risk_tier=MEDIUM, action_type=core_pull_transfer.

- On router clearance: (1) Create new employee_allocations record for Core demand. (2) Set Speciality allocation.status=CORE_PULLED, end_date=TODAY. (3) Update employees.delivery_engine=CORE if not already set. (4) Log in employee_engine_history.

- Notify Speciality RM immediately: 'CORE PULL: [Employee Name] reallocated to Core demand [demand_id] for [client]. Effective today. Please plan replacement sourcing.'

- Notify BU Head: 'Core-Pull executed: [name] moved from [Specialty client] to [Core client]. Specialty pool now at [N] Core-Certified.'

## Step 3: Build BU Head override path

- POST /api/core-pull/{event_id}/override: Auth BU Head only. body { justification (min 100 chars) }.

- Override logged in core_pull_events.override_justification. Specialty allocation continues. Core demand flagged for alternative sourcing.

- More than 2 Core-Pull overrides in 30 days: Director alert. Override culture is a signal that Core pool is insufficient.

## Business Rules

## BR: Core Pull Is Same-Day — Not Next Week

- CorePullEngine.execute() creates the Core allocation with start_date=TODAY. The Specialty allocation ends TODAY. There is no negotiation period. The employee is Core-deployed from the moment the engine executes.

- Field: Reallocation effective date = execution date, no delay

## BR: Override Requires 100-Character Justification and Is Director-Visible

- BU Head override of a Core-Pull requires minimum 100 characters of justification. Every override is included in the Director's weekly compliance review. Overrides are a compliance signal — they should be rare.

- Field: 100-char min justification. Director visibility.

## BR: Specialty RM Notified Before Client

- Specialty RM receives the Core-Pull notification before any client (PwC/EY) is informed. RM coordinates the handover communication with the Specialty client. WROS does not notify Specialty clients directly.

- Field: RM notified first — client communication is human-managed

## Acceptance Criteria

- AC-1: Core-Pull detected within one scan cycle (30 min)

- AC-2: Reallocation effective same day — no delay

- AC-3: Specialty RM notified before any other party

- AC-5: 2+ overrides in 30 days alerts Director

- AC-6: All events logged in core_pull_events permanently
