## Why — Business Rationale

- The moment an opportunity is won, it needs to become something operational — a project with a billing type, dates, an owner, and a status that moves through its own lifecycle. Creation and status tracking were originally two stories, but a project's status is really just an attribute of the same record its creation produces, not a separate concept.

## What — Scope

- Automatic project creation from a won opportunity — client, billing type, dates, owner, continent, currency inherited — plus the project's status lifecycle (Planning → Active → On Hold → Completed → Closed).

## Before — Prerequisites

- S-236 must be live — projects originate from won opportunities.

## Implementation Steps

## Step 1: Build the auto-creation trigger

- On opportunity.stage transitioning to Won (via S-237's Kanban), auto-create a project record inheriting client_id, currency, continent, and the opportunity's revenue figures.

## Step 2: Build manual project creation

- For projects not originating from a tracked opportunity (e.g., an existing client's follow-on work) — same underlying record, different entry path.

## Step 3: Build the status lifecycle

- Planning → Active → On Hold → Completed → Closed, with each transition logged via HRMS-0118.

## Business Rules

BR: BR-0801-01 — A project auto-created from a won opportunity inherits client, currency, and continent without re-entry

- Prevents data entry drift between the opportunity and its resulting project — the same client record, same currency assumption, carried forward automatically.

- Field: Project creation from Won opportunity copies client_id, currency, continent directly, no manual re-selection
