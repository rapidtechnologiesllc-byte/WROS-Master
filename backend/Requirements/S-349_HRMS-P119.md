## 2. WHY THIS EXISTS

Thunder currently responds to candidates. The Proactive Motivation Engine makes Thunder proactively reach out with the exact right message at the exact right moment — driven by the candidate's desire profile — to increase the probability of them saying YES to BlitzenX.

Example: Desire profile shows top desire=CAREER_GROWTH, engagement=WARM, has_competing_offer=TRUE. Without prompting, Thunder sends: 'Hi John — I just wanted to share something. One of our Guidewire consultants who joined BlitzenX 2 years ago at your level was promoted to Technical Lead within 18 months. I think BlitzenX could offer that same trajectory for you. Would that kind of growth path matter to you in your decision?' This message is perfectly targeted, unprompted, and hits exactly what John cares about.

This is Thunder doing what the best human recruiters do — understanding what a candidate needs and proactively addressing it before they have to ask.

## 3. WHAT YOU ARE BUILDING

## 5. STEP-BY-STEP EXECUTION

▶  Follow these steps in exact order. If a step is unclear, ask the lead BA — never assume.

## Step 1: Build motivation content library (Lead BA must provide and approve all content)

- Store in system_configuration per tenant — key=MOTIVATION_{category}_{type}, value=JSON array of content items

- CAREER_GROWTH content: ['BlitzenX Guidewire consultants average 2 promotions in 3 years', 'Our technical mentorship program pairs all new joiners with a senior Guidewire architect for 6 months', 'BlitzenX funded 3 Guidewire certifications for our team in 2024']

- COMPENSATION content: ['BlitzenX offers performance bonuses averaging 15% of annual salary', 'Our salary revision cycle is every 6 months for consultants demonstrating impact', 'Market rate for Guidewire PolicyCenter specialists is [X] — BlitzenX offers in this range']

- STABILITY content: ['BlitzenX has been placing Guidewire specialists since 2015', '94% of our clients are on multi-year contracts', 'Average BlitzenX consultant tenure is 3.2 years']

- REMOTE_FLEXIBILITY content: ['BlitzenX offers hybrid work arrangements negotiated per client', 'We have placed 12 consultants in full-remote Guidewire roles in the last 12 months']

- COMPANY_REPUTATION content: ['BlitzenX clients include [top 3 clients if shareable]', 'Our Glassdoor rating is [X]', 'Featured in [industry publication] as a top Guidewire staffing firm']

- All content is BA-approved — Thunder never fabricates facts. It only uses content from this library.

## Step 2: Build motivation trigger detection

- Triggers for proactive motivation message (checked by Supervisor Agent every cycle):

- TRIGGER 1 — COMPETING_OFFER: has_competing_offer=true AND offer.status=RELEASED → send immediately

- TRIGGER 2 — OFFER_PENDING_RESPONSE: offer.status=RELEASED AND days_since_release >= 2 AND no acceptance/decline yet → send motivation

- TRIGGER 3 — COOLING_ENGAGEMENT: engagement_level drops from HOT/WARM to COOL → send re-engagement motivation

- TRIGGER 4 — DESIRE_SHIFT: candidate.desire_shift_detected event → send message aligned to new top desire

- TRIGGER 5 — SCHEDULED_NURTURE: every 7 days for WARM candidates in QUALIFIED or INTERVIEW_SCHEDULED state → send value-add message

- Max 1 proactive motivation message per candidate per 48 hours (prevent spamming).

## Step 3: Build generateMotivationMessage() function

- generateMotivationMessage(candidate_id, tenant_id, trigger_type) → message text

- Load: desire_profile (top desire + fear), motivation content library items for top_desire_category, candidate name, memory facts, conversation state

- Load candidate's preferred channel and optimal send time (time of day they typically respond fast, from response_speed signals)

- Build MOTIVATION prompt: 'You are Thunder, Talent Scout at BlitzenX. You are writing a personalized, proactive outreach message to a candidate to motivate them toward accepting the BlitzenX opportunity. The candidate's strongest desire is {top_desire_category} (score: {score}). Their primary concern is {primary_fear}. Trigger: {trigger_type}. Approved BlitzenX facts for {top_desire_category}: {content_library_items}. Candidate name: {name}. Current conversation context: {memory_summary}. Write a warm, 2-3 sentence message that: (1) does NOT feel like a sales pitch, (2) uses ONE specific fact from the approved content library, (3) naturally connects that fact to what YOU KNOW this specific candidate cares about, (4) ends with a soft open question. Use ONLY the provided approved facts — never invent statistics.'

- Validate: message must contain a fact from the content library. Message must be 2-3 sentences. No generic phrases like 'just checking in'.

## Step 4: Build optimal send timing

- Analyze candidate's response_speed signals by time_of_day: when is their fastest response time?

- Example: candidate typically replies within 30 minutes between 7-9 PM. That is their peak engagement window.

- Schedule motivation message to send at the next occurrence of their peak engagement window.

- If no pattern detected: default to 8 AM candidate local time.

- Use ScheduledMotivationJob: runs every 30 minutes, sends due motivation messages.

## Step 5: Build motivation outcome tracking

- After motivation message sent: track what happens next. Did candidate reply within 24h? Did they accept the offer? Did engagement level improve?

- INSERT motivation_outcomes: { candidate_id, trigger_type, message_sent, desire_category_targeted, response_within_24h BOOLEAN, engagement_change (HOT/WARM/COOL before and after), offer_accepted BOOLEAN }

- This outcome data feeds the learning feedback loop — over time, the system learns which motivation approaches work best for which desire profiles.

## 6B. BUSINESS RULES

▶  Every rule is non-negotiable. If in doubt, escalate to lead BA — never silently skip a rule.

## BR-01: Thunder ONLY Uses BA-Approved Facts — Never Fabricates

generateMotivationMessage() prompt explicitly instructs the LLM to use ONLY facts from the motivation content library. The LLM is explicitly told: 'never invent statistics'. After generation, validation checks that the message contains at least one string from the content library items. If no library fact is present: regenerate or fall back to a safe message.

↳ Triggered by field: Content library facts only — never fabricated

## BR-02: Maximum 1 Motivation Message Per Candidate Per 48 Hours

Even if multiple triggers fire simultaneously: only one motivation message per candidate per 48-hour window. Priority: COMPETING_OFFER > OFFER_PENDING > COOLING_ENGAGEMENT > DESIRE_SHIFT > SCHEDULED_NURTURE. The highest-priority trigger wins.

↳ Triggered by field: 1 per 48h per candidate limit

## BR-03: Motivation Messages Target TOP Desire — Not Secondary

generateMotivationMessage() always targets the candidate's top_desire_category. If career growth is #1 and compensation is #2: the message is about career growth. This ensures maximum relevance. The secondary desire may be addressed by HR in person (HRMS-P120).

↳ Triggered by field: top_desire_category targeted always

## BR-04: Candidate with No Desire Profile Receives Generic Nurture Only

If a candidate has no desire_profile yet (not enough signals processed): send generic BlitzenX value message (the same as HRMS-P302 passive nurture). Do NOT attempt motivation without a profile — generic motivation is noise.

↳ Triggered by field: Require desire_profile before targeted motivation
