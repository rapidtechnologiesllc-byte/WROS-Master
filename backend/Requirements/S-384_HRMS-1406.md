## Why — Business Rationale

- A cadence rule and a resolved level are only useful if something actually acts on them — this agent is what turns 'Technical Managers should talk to their reports weekly' from a policy into a real calendar invite that shows up on both people's calendars without either of them having to remember to book it.

## What — Scope

- A scheduled agent that, for every manager-report pair, checks whether a check-in matching S-383's cadence for the manager's resolved level is due, and if so books a calendar meeting via the S-380 Outlook integration, with rescheduling support if either party declines.

## Before — Prerequisites

- S-382 and S-383 must be live — this agent reads resolved levels and cadence configuration, it doesn't define either.

- S-380 Embedded Outlook Calendar must be live and the Graph API calendar-write scope must be available for actually creating the invite.

## Implementation Steps

## Step 1: Build the daily due-check scan

- For every manager-report pair (derived from S-382's hierarchy), check days since last logged check-in against S-383's cadence for the manager's resolved level.

- A pair with no check-in history at all is treated as immediately due, not skipped.

## Step 2: Build the calendar booking action

- For due pairs, propose a meeting slot using both parties' free/busy data from the embedded Outlook Calendar (S-380) and book it via Graph API, titled generically ("[Manager] / [Report] Check-in") rather than exposing any performance-review framing.

## Step 3: Build decline/reschedule handling

- If either party declines the invite, the agent proposes an alternate slot within the same week rather than simply dropping the check-in — a declined invite is a scheduling conflict to solve, not cause to skip the check-in entirely.

## Step 4: Log completed check-ins

- On the meeting's scheduled time passing (not on completion confirmation, since this agent has no way to know what was discussed), the pair's last-check-in date updates, resetting the cadence clock for that pair.

## Business Rules

## BR: BR-1406-01 — This is a scheduled batch job, not a real-time agent

- Matches the same reasoning already established for HRMS-1109/1110 — there is no action here that benefits from real-time triggering, so it runs daily rather than carrying real-time agent scaffolding (action-intent events, Orchestration Router registration) it doesn't need.

- Field: No agent.action.intent events published, no Orchestration Router registration — same deliberate simplification as HRMS-1109/1110

## BR: BR-1406-02 — A declined invite triggers rescheduling, never silent cancellation

- The whole purpose of this system is making sure check-ins actually happen across a changing org — letting a declined invite quietly disappear the cadence for that pair defeats that purpose.

- Field: check_in_status=DECLINED automatically triggers a reschedule proposal within the same cadence cycle, never a silent skip

## BR: BR-1406-03 — Meeting titles are generic, with no performance-review framing

- This is a connection/check-in cadence, not an implied performance review — the calendar invite itself should not create anxiety or imply evaluation is happening.

- Field: Calendar event title is a fixed template ('[Manager] / [Report] Check-in'), never dynamically includes performance language

## Acceptance Criteria

- AC-1: A manager-report pair with no prior check-in history is scheduled on the next scan cycle, not skipped as 'not yet due.'

- AC-2: A declined invite triggers an automatic reschedule proposal rather than the check-in simply disappearing from tracking.

- AC-3: Every booked meeting uses the generic, non-performance-framed title template.

- AC-4: Changing a level's cadence in S-383 correctly changes when that level's pairs are next flagged due, verified across a scan cycle.

## Not In Scope

- No automatic performance content generation for these meetings — this is purely a scheduling agent, S-355's Reporting Manager Weekly Input Bot remains the separate, distinct performance-input mechanism.

- No agenda-setting or meeting-notes capture in this story — it books time, what happens in the meeting is between the two people.
