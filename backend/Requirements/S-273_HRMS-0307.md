## Why — Business Rationale

- When a demand plan is approved and gap analysis confirms external hiring is needed, the sourcing workflow must start automatically. Manual sourcing trigger delays the pipeline by days or weeks. This story closes the loop between planning and execution — approved plan → automatic sourcing starts within minutes.

## What — Scope

- Build the sourcing workflow trigger: when demand plan is approved or a new open demand is created with no bench match, automatically route to correct sourcing channel (bench redeploy / HTD intake / LinkedIn / sub-vendor) based on role type and urgency.

## Before — Prerequisites

- HRMS-0303 demand plan approval. HRMS-0306 gap analysis. HRMS-0308 bench-first policy enforcement.

## Implementation Steps

## Step 1: Build SourcingWorkflowTrigger service

- SourcingWorkflowTrigger.trigger(demand_plan_item_id or demand_id): reads sourcing_strategy on demand item. Routes: BENCH_REDEPLOY → notify RM with top 3 bench matches (from HRMS-0509). HTD → create HTD intake slot and notify HTD coordinator. EXTERNAL_HIRE → trigger HRMS-P401 LinkedIn agent with job requirements + trigger HRMS-0309 job req creation. SUBVENDOR → create sub-vendor request (HRMS-P803) for approved vendors with matching specialization.

- Log all triggers in sourcing_workflow_log: demand_id, trigger_type, triggered_at, triggered_by_system=true.

## Step 2: Build sourcing workflow status tracking

- CREATE TABLE sourcing_workflow_log: id UUID PK, tenant_id UUID, demand_id UUID, sourcing_strategy VARCHAR(50), status ENUM('TRIGGERED','IN_PROGRESS','FILLED','CANCELLED'), triggered_at TIMESTAMP, filled_at TIMESTAMP nullable, days_to_fill INTEGER nullable, notes TEXT.

- GET /api/workforce-planning/sourcing-status?demand_id=X: returns workflow log entries for this demand.

- RM Dashboard (HRMS-P203) shows sourcing pipeline per open demand.

## Business Rules

## BR: Bench-First Check Mandatory Before Any External Sourcing Trigger

- SourcingWorkflowTrigger MUST call GapAnalysisEngine.analyze() before routing to EXTERNAL_HIRE or SUBVENDOR channels. If bench supply covers the gap: route to BENCH_REDEPLOY only. Block external sourcing until RM confirms bench is insufficient. This is HRMS-0308 policy enforcement at the execution layer.

- Field: Bench check gates external sourcing — no bypass

## BR: Sourcing Strategy Determined by Role Type — Not Manual Selection

- Sourcing strategy is auto-assigned: Guidewire lateral hires → EXTERNAL_HIRE + SUBVENDOR. Java 5yr+ developers → HTD (if HTD intake not paused) + EXTERNAL_HIRE. Bench employees matching skills → BENCH_REDEPLOY. RM can override strategy with justification logged.

- Field: Auto-assigned sourcing strategy with RM override option
