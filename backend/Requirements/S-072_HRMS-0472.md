## 2. WHY THIS EXISTS

Candidates raise objections: 'The salary seems too low', 'I'm not sure about relocating to Austin', 'I'm happy where I am and not actively looking'. Each objection requires a specific, thoughtful response that acknowledges the concern, provides relevant information, and keeps the conversation alive. Thunder must handle these objections professionally without dismissing them or pushing aggressively.

Generic responses to objections ('I understand, let me check') lose candidates. Personalized, fact-based responses built from the candidate's memory and the job context keep them engaged.

## 3. WHAT YOU ARE BUILDING

Build handleObjection() — when HRMS-0433 detects intent=objecting, route to this engine. Classifies objection type, loads relevant context, generates tailored response using OBJECTION_HANDLING prompt, records the objection in candidate memory.

## 5. STEP-BY-STEP EXECUTION

▶  Follow these steps in exact order. If a step is unclear, ask the lead BA — never assume.

## Step 1: Define objection taxonomy

- Classify objections into types (BA must approve this list):

- SALARY: concerns about compensation ('salary too low', 'looking for more', 'not matching expectations')

- LOCATION: concerns about work location ('not relocating', 'prefer remote', 'too far from home')

- ROLE_FIT: concerns about the role ('not my area', 'different domain', 'not what I expected')

- TIMING: not ready to move ('happy where I am', 'just got a raise', 'committed to current project')

- COMPANY: concerns about BlitzenX ('not familiar with company', 'what do you do?')

- PROCESS: concerns about the hiring process ('too many rounds', 'when will I hear back?')

- OTHER: any objection that doesn't fit above

## Step 2: Build classifyObjection() function

- classifyObjection(message_body) → { objection_type, key_concern, confidence }

- Use LLM with classification prompt: 'Classify this objection from a job candidate into one of: SALARY, LOCATION, ROLE_FIT, TIMING, COMPANY, PROCESS, OTHER. Also identify the key specific concern in max 10 words. Return JSON: { objection_type, key_concern, confidence }. Message: [{message_body}]'

## Step 3: Build handleObjection() function

- handleObjection(candidate_id, tenant_id, message_body) → Thunder's response message

- Step 1: classifyObjection() to get type

- Step 2: load candidate memory + job context for this candidate

- Step 3: build OBJECTION_HANDLING prompt with: objection_type, key_concern, candidate memory (salary expectations, location preferences, role interests), job details (salary range if we can share it, remote/hybrid status, role description)

- Step 4: callLLM() with OBJECTION_HANDLING prompt

- Step 5: store objection in candidate_memory_facts: category=OBJECTION, fact_key=objection_type, fact_value=key_concern

- Step 6: return Thunder's response message

- Escalation rule: if SAME objection type raised 3+ times in same conversation: do not re-handle — escalate to recruiter instead

## Step 4: Wire to conversation flow

- In HRMS-0425 QualificationConversationService: when intent=objecting → call handleObjection() → send Thunder's response → continue qualification if candidate re-engages

- After Thunder's objection response: next message from candidate re-checked for intent. If intent=answering_question: resume normal qualification. If still objecting: check objection count.

## 6B. BUSINESS RULES

▶  Every rule is non-negotiable. If in doubt, escalate to lead BA — never silently skip a rule.

## BR-01: Same Objection 3 Times = Escalate to Recruiter

If candidate raises the same objection_type more than 3 times in the same conversation: Thunder stops trying to handle it and escalates to recruiter. The recruiter has more authority to address structural concerns (e.g. actual salary negotiation flexibility).

↳ Triggered by field: objection count per type >= 3

## BR-02: Salary Objections Never Include Specific Numbers Without Approval

When responding to SALARY objections, Thunder must NEVER quote specific salary numbers (budget, range, flexibility) unless those numbers are explicitly provided in the job record and marked as shareable=true. Thunder says 'Let me connect you with our team to discuss compensation in detail' if no shareable salary data available.

↳ Triggered by field: SALARY objection response rule
