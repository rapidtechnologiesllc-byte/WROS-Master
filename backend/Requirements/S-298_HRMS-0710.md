## 2. WHY THIS EXISTS

The recruiter has 15 qualified candidates and a demand for 2 positions. Who gets submitted first? The AI ranking provides an objective, documented, auditable answer using the overall_score from HRMS-0440 combined with eligibility status. The client always receives BlitzenX's best-matched candidates first.

## 3. WHAT YOU ARE BUILDING

Build getRankedCandidatesForSubmission(demand_id) — extends HRMS-0440 getRankedCandidates() with additional submission eligibility checks. Returns a sorted, eligibility-filtered list ready for the submission pipeline.

## 5. STEP-BY-STEP EXECUTION

▶  Follow these steps in exact order. If a step is unclear, ask the lead BA — never assume.

## Step 1: Build getRankedCandidatesForSubmission()

- getRankedCandidatesForSubmission(demand_id, tenant_id) → array of { candidate_id, name, overall_score, is_eligible, eligibility_blockers, submission_priority_rank }

- Load all candidate_job_scores for this demand_id. Ordered by overall_score DESC.

- For each candidate: run checkExperienceEligibility() (HRMS-P601) + checkMarketProfileRule() (HRMS-P605) + checkEmploymentTypeRule() (HRMS-P606).

- is_eligible = all three checks pass. eligibility_blockers = list of failed checks.

- submission_priority_rank = rank among ELIGIBLE candidates only (ineligible candidates appear at bottom with their blockers noted).

## Step 2: Build GET /api/demands/{id}/ranked-candidates endpoint

- Auth: recruiter auth. Returns getRankedCandidatesForSubmission() result.

- Used by submission pipeline to show which candidates to submit and in what order.

## BR-01: Ineligible Candidates Shown but Not Ranked

Ineligible candidates (experience, market profile, C2C) appear at the bottom of the list clearly marked INELIGIBLE with their specific blocker. They are not ranked against eligible candidates. Recruiters see them for context but cannot select them for submission.

↳ Triggered by field: INELIGIBLE = no rank, shown separately
