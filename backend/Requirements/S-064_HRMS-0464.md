## 2. WHY THIS EXISTS

A recruiter sees Thunder's message in the conversation timeline: 'Thank you for sharing your notice period! Could you share your current salary?' The recruiter wants to know WHY Thunder asked that specific question at that moment. The Explainability Panel shows: 'Thunder asked because: The candidate just answered their notice period question (field #3). Current salary (field #4) is the next highest-priority missing field. Profile completeness was 40% before this message.'

Transparency builds trust. Recruiters who understand Thunder's reasoning are more confident letting it run autonomously and better at catching errors.

## 3. WHAT YOU ARE BUILDING

Build an expandable Explainability Panel for every Thunder message in the conversation timeline. Clicking a Thunder message shows: why Thunder sent it (from thunder_response_log.explanation_text), what prompt type was used, what context Thunder had at that moment.

## 5. STEP-BY-STEP EXECUTION

▶  Follow these steps in exact order. If a step is unclear, ask the lead BA — never assume.

## Step 1: Link thunder_response_log to conversation_messages

- ALTER TABLE conversation_messages ADD COLUMN IF NOT EXISTS thunder_response_log_id UUID nullable FK→thunder_response_log.id

- When HRMS-0434 stores a Thunder message in conversation_messages: also set thunder_response_log_id

- This creates the link between the visible message and Thunder's internal reasoning

## Step 2: Build GET /api/messages/{id}/explanation endpoint

- Auth: recruiter auth. Must own this tenant.

- Load thunder_response_log WHERE id = conversation_messages.thunder_response_log_id

- Response: { explanation_text, prompt_type, context_snapshot: { completeness_at_time, state_at_time, missing_fields_at_time, memory_facts_count }, generated_at, model_used }

- Returns HTTP 404 if message has no thunder_response_log (e.g. recruiter manual messages)

## Step 3: Build Explainability Panel UI in ConversationTimeline

- In HRMS-0405 MessageBubble: for Thunder messages (sender_type=AI), add a small 'Why?' link below the message text

- Click 'Why?': expand an inline panel below the message bubble showing the explanation

- Panel shows: 'Thunder sent this because: [explanation_text]'. Below: 'Type: [prompt_type friendly name]'. Below: small gray section showing context snapshot: 'At this moment: Profile [X]% complete | State: QUALIFYING | Memory facts: [N] | Missing fields: [list]'

- Panel is collapsible — click again to close

- 'Why?' link only appears on Thunder messages. Not on recruiter or candidate messages.

## Step 4: Build immutable explanation log viewer for audit

- GET /api/candidates/{id}/thunder-explanation-log — returns all thunder_response_log records for this candidate ordered by created_at

- Shows full history of every Thunder decision for this candidate

- Accessible to recruiter role. Data never editable or deletable.

## 6B. BUSINESS RULES

▶  Every rule is non-negotiable. If in doubt, escalate to lead BA — never silently skip a rule.

## BR-01: Explanation Text Is Immutable — Never Updated After Creation

thunder_response_log.explanation_text is written once when Thunder generates the message. It captures Thunder's reasoning at that exact moment. It is never updated — even if the candidate's situation changes later.

↳ Triggered by field: thunder_response_log (insert-only)

## BR-02: 'Why?' Link Only on Thunder Messages

The 'Why?' link only appears next to messages where sender_type=AI. Recruiter messages and candidate messages do not have explanation panels — only Thunder's autonomous messages do.

↳ Triggered by field: sender_type=AI only
