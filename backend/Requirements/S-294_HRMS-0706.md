## 2. WHY THIS EXISTS

Interview outcomes must be structured and logged for the Core Eligibility Gate (HRMS-0513) and for audit purposes — unstructured recruiter notes cannot be scored consistently or fed into the Core Eligibility AI Assessor later.

A locked, structured scorecard also gives R-05 (L1 must pass before L2) a concrete outcome value to gate against, instead of relying on someone remembering to relay a verbal result.

## 3. WHAT YOU ARE BUILDING

Build: (1) InterviewPanelAssigner. (2) Structured scorecard capture. (3) Outcome propagation and L1/L2 gate unlock. (4) Immutability and audit-correction workflow.

## 5. STEP-BY-STEP EXECUTION

▶ Follow these steps in exact order. If a step is unclear, ask the lead BA — never assume.

## Step 1: Panel Assignment

- RM or Recruiter assigns a Technical Manager as interviewer from the role=Technical Manager list via PATCH /api/interviews/{id}/assign-panel.

- Assignment is logged; the interviewer is notified via the HRMS-0113 Notification Engine.

## Step 2: Structured Scorecard Schema

- CREATE TABLE interview_scorecards: id UUID PK, tenant_id UUID, interview_id UUID, technical_depth_rating INTEGER, communication_rating INTEGER, problem_solving_rating INTEGER, guidewire_domain_fit_rating INTEGER, outcome ENUM('PASS','FAIL'), notes TEXT, submitted_by UUID, submitted_at TIMESTAMP, locked BOOLEAN default true.

- All four rating fields are required (1–5 integer); outcome is required before the POST succeeds.

## Step 3: Outcome Propagation

- On scorecard submit, interviews.outcome=scorecard.outcome, interviews.status=COMPLETED.

- If interviews.type=L1 and outcome=PASS: unlock L2 scheduling for the same submission_id (checked by HRMS-0705's BR-01 gate).

- If outcome=FAIL: submissions.status is set to REJECTED with a system note referencing the interview.

## Step 4: Immutability & Correction

- Once submitted, interview_scorecards.locked=true and no field can be edited via the standard API.

- A correction requires a Technical Manager to submit an interview_scorecard_corrections record with old_value, new_value, and a mandatory reason — never a silent overwrite.

## 6B. BUSINESS RULES

▶ Every rule is non-negotiable. If in doubt, escalate to lead BA — never silently skip a rule.

## BR-01: L1 Must Pass Before L2 (R-05)

Enforced at the HRMS-0248 InterviewPanelAssigner gate — an L2 interview record's scheduling and creation is blocked until the linked L1 interview_scorecards.outcome=PASS is submitted and locked.

↳ Triggered by field: outcome

## BR-02: Scorecard Immutable After Submit

Once interview_scorecards.locked=true, no field can be changed via a direct UPDATE. Any correction must go through interview_scorecard_corrections with a Technical Manager identity and a mandatory reason string.

↳ Triggered by field: locked
