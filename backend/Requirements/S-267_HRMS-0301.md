## Why — Business Rationale

- BlitzenX's BU Heads set annual and quarterly revenue targets. Without targets stored in WROS, the workforce planning engine has nothing to plan against. Revenue target is the input that drives every hiring decision downstream — how many people to hire, which skills, what delivery engine (Speciality vs Core).

## What — Scope

- Build: (1) BU revenue target CRUD — set target per BU per planning horizon (3/6/12 months). (2) Target history — track target changes over time. (3) Target vs actual variance — compare target against revenue_records actuals from HRMS-0601.

## Before — Prerequisites

- HRMS-0107 business_units table. HRMS-0212 revenue dashboard for actuals.

## Implementation Steps

## Step 1: Create bu_revenue_targets table

- CREATE TABLE bu_revenue_targets: id UUID PK, tenant_id UUID, bu_id UUID FK→business_units.id, target_period ENUM('Q1','Q2','Q3','Q4','H1','H2','ANNUAL'), fiscal_year INTEGER, target_amount_usd_cents BIGINT NOT NULL, created_by UUID, created_at TIMESTAMP, notes TEXT nullable

- One record per BU per period per year. Upsert on change — keep history via created_at ordering.

## Step 2: Build target CRUD API and UI

- POST /api/workforce-planning/targets: body { bu_id, target_period, fiscal_year, target_amount_usd_cents, notes }. Auth: BU Head, Director, Admin.

- GET /api/workforce-planning/targets?bu_id=X&fiscal_year=Y: returns all targets for BU with actuals pulled from revenue_records.

- UI: /admin/workforce-planning/targets. Table per BU: target period, target amount, actual YTD, variance %, status (ON_TRACK/AT_RISK/BEHIND).

## Step 3: Build target vs actual comparison

- On each target record: join to analytics_fact_revenue to compute actual_ytd_usd_cents for the period.

- variance_pct = (actual - target) / target * 100. Status: >95% ON_TRACK, 80-95% AT_RISK, <80% BEHIND.

- Color-coded status badge. Trend line showing monthly actuals vs target trajectory.

## Business Rules

## BR: Only BU Head, Director and Admin Can Set Revenue Targets

- Revenue targets are strategic commitments. Recruiter and RM roles see targets read-only. CS cannot see targets.

- Field: BU Head / Director / Admin write access only

## BR: Target Cannot Be Deleted — Only Superseded

- Once a target is set, it cannot be deleted. A new target for the same period creates a new record with a new created_at. The most recent record is the active target. Historical targets remain visible for variance analysis.

- Field: Append-only target history
