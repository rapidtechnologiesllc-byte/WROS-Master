## Why — Business Rationale

- A client with a question today either emails someone directly (invisible to the rest of the CS team, lost the moment that person is out) or calls (no record at all). One in-portal thread per topic type gives every client question a home, a response SLA, and a permanent record any CS team member can pick up.

## What — Scope

- An in-portal messaging thread, typed by topic (General / Submission Query / Timesheet Issue / RFP Query / Project Update), with CS responding from within WROS and a 4-business-hour response SLA that escalates to the CS manager on breach.

## Before — Prerequisites

- HRMS-P702 Client Portal base access must be live.

## Implementation Steps

## Step 1: Build the message composer

- Available from any client portal page, topic-typed on send.

## Step 2: Build the CS-side reply interface

- CS replies from within WROS, not a separate email client — keeps the thread in one place.

## Step 3: Build the SLA tracker

- 4-business-hour response clock starts on client message; breach triggers an alert to the CS manager, not just a delayed reply.

## Business Rules

## BR: BR-0725-01 — 4-business-hour response SLA breach escalates to the CS manager

- A missed response window isn't just a delayed reply — it's a management-visibility event, since client responsiveness is a relationship-health signal (feeds S-198's health score).

- Field: response_time > 4 business hours triggers HRMS-0113 alert to cs_manager_id
