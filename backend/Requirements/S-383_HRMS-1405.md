## Why — Business Rationale

- A BU Head talking to each direct report quarterly and a Technical Manager talking to theirs weekly are both '1:1 check-ins' but at completely different frequencies — the cadence itself needs to be explicit, editable configuration tied to the level resolved by S-382, not a number buried in code that only a developer can change when the business decides quarterly should become monthly.

## What — Scope

- An Admin-editable mapping from each configured org level (per S-382) to a check-in cadence — the current baseline being BU Head-to-report quarterly, Principal Architect monthly, Technical Manager weekly — with sensible defaults for any newly-added level until explicitly configured.

## Before — Prerequisites

- S-382 must be live — cadence is defined per resolved level, which S-382 produces.

## Implementation Steps

## Step 1: Build the cadence configuration table

- One row per level (from S-382's configured list): level_name, cadence_days, applies_to ('direct_reports' — always relative to the level holder's own direct reports, not further down the chain).

## Step 2: Seed current baseline cadences

- BU Head: 90 days (quarterly). Principal Architect: 30 days (monthly). Technical Manager: 7 days (weekly) — matching the current org structure's stated cadences exactly.

## Step 3: Build the new-level default handling

- When S-382's level list gains a new entry with no cadence configured yet, default it to a conservative fallback (e.g., 30 days) and flag it for Admin review — never silently unscheduled, never silently assumed to be the same as a neighboring level.

## Step 4: Build the Admin cadence editor

- Simple per-level cadence editing screen, changes take effect on S-384's next scheduling run, logged via HRMS-0110 audit trail same as any other HRMS-0115 config change.

## Business Rules

## BR: BR-1405-01 — Cadence is always relative to the level holder's own direct reports

- A BU Head's quarterly cadence applies to people who report directly to them, not to everyone several levels below — this keeps the scheduling load correctly distributed rather than one senior person owing check-ins to the entire organization beneath them.

- Field: applies_to is fixed to 'direct_reports', not configurable to a broader scope, to keep this unambiguous

BR: BR-1405-02 — A newly configured level defaults conservatively and is flagged, never silently unscheduled

- If S-382 gains a new level and this story has no cadence for it, the safe failure is 'schedule something reasonable and flag it for review,' not 'skip check-ins for that level entirely until someone notices.'

- Field: new_level_default_flag=true on any level with no explicit cadence entry, defaults to 30 days until Admin confirms

## BR: BR-1405-03 — Cadence changes are audit logged and apply only to future scheduling

- Matches HRMS-0110's standard audit discipline for config changes; retroactively rescheduling already-booked check-ins on a cadence change would be disruptive and confusing.

- Field: Cadence edits write to audit_log per HRMS-0110; S-384 only reads current cadence at scheduling time, does not reschedule existing bookings

## Acceptance Criteria

- AC-1: The three baseline cadences (BU Head 90 days, Principal Architect 30 days, Technical Manager 7 days) are correctly seeded and editable.

- AC-2: A newly-added level with no configured cadence defaults to 30 days and is visibly flagged for Admin review.

- AC-3: A cadence change is audit logged and does not retroactively alter already-scheduled check-ins.
