## Why — Business Rationale

- EPIC-11's agents run unattended overnight specifically because BlitzenX trusts the platform to fail loudly rather than silently. That trust has one precondition: every error, anywhere in the system, lands in one structured, queryable place — not scattered across console output nobody's watching at 3am.

## What — Scope

- Centralized structured error capture with severity classification and alerting on critical failures, consumed both by human on-call review and by HRMS-1108's automated health checks.

## Before — Prerequisites

- None — this is early infrastructure, but doesn't block the build order the way HRMS-0109 does.

## Implementation Steps

## Step 1: Create error_log table

- Run CREATE TABLE per Data Mapping.

- Columns: error_type, severity, stack_trace, request_context, tenant_id (nullable — some errors are pre-auth), timestamp.

## Step 2: Build the structured logging wrapper

- All application code logs through one wrapper function, not raw console/print statements.

- Wrapper classifies severity (INFO/WARN/ERROR/CRITICAL) based on error type taxonomy.

## Step 3: Wire CRITICAL alerting

- CRITICAL severity triggers an immediate HRMS-0113 P0 notification to on-call.

- ERROR severity batches into an hourly digest; WARN/INFO logged only.

## Step 4: Expose the error log to HRMS-1108

- Read API filtered by integration_name/time_window, used by the Integration Health Agent's classification calls.

## Business Rules

## BR: BR-0117-01 — CRITICAL errors always page immediately, never batch

- Matches the pattern used throughout EPIC-11 — a CRITICAL error is by definition something that can't wait for a digest.

- Field: severity=CRITICAL triggers HRMS-0113 P0 send synchronously as part of the logging call

## BR: BR-0117-02 — No raw console logging in application code

- Every error path goes through the structured wrapper — enforced by lint rule, not just convention, so nothing is invisible to the centralized log.

- Field: CI lint rule flags any direct console.error/print usage outside the wrapper

## Acceptance Criteria

- AC-1: A CRITICAL-classified error triggers an HRMS-0113 P0 notification within the same request cycle it occurred.

- AC-2: A direct console.error call outside the wrapper is flagged and fails CI lint.

- AC-3: HRMS-1108 can successfully query error_log filtered by integration name and time window.
