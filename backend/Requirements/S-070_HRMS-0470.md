## 2. WHY THIS EXISTS

Recruiters need to understand how engaged each candidate is — not just whether they replied, but how quickly, how consistently, and how positively. These metrics help recruiters make decisions: 'Should I push for an interview with this candidate or wait for stronger engagement signals?'

## 3. WHAT YOU ARE BUILDING

Build calculateEngagementHealth(candidate_id) — computes per-candidate engagement metrics: response rate, avg response time, messages exchanged, days to qualification, sentiment score. Store in candidate_engagement_metrics table. Display on candidate profile card.

## 4. BEFORE YOU START

## 5. STEP-BY-STEP EXECUTION

▶  Follow these steps in exact order. If a step is unclear, ask the lead BA — never assume.

## Step 1: Create candidate_engagement_metrics table

- id UUID PK, tenant_id UUID, candidate_id UUID UNIQUE FK→candidates.id, response_rate DECIMAL(5,2) (% of outbound AI messages that received an inbound reply), avg_response_time_minutes INTEGER, total_messages_exchanged INTEGER, days_to_qualification INTEGER nullable (null if not qualified yet), avg_sentiment_score DECIMAL(3,2) (-1 to 1 scale), last_inbound_at TIMESTAMP nullable, metrics_calculated_at TIMESTAMP

## Step 2: Build calculateEngagementHealth() function

- response_rate: COUNT(inbound) / COUNT(outbound AI messages) * 100. Cap at 100%.

- avg_response_time_minutes: for each inbound message, find preceding outbound AI message. Calculate difference in minutes. Average across all pairs. Only count pairs where gap < 7 days (exclude ghosting periods).

- total_messages_exchanged: COUNT(*) from conversation_messages for this candidate

- days_to_qualification: if candidate has QUALIFIED state in conversation_state_history: (qualified_at - first_message_at) in days. Else null.

- avg_sentiment_score: AVG(sentiment mapped to -1,0,1) from candidate_sentiment_log. NEGATIVE=-1, NEUTRAL=0, POSITIVE=1.

- UPSERT into candidate_engagement_metrics

## Step 3: Build EngagementMetricsJob (runs every 4 hours)

- Recalculate for all active candidates

- Publish event: candidate.engagement_metrics_updated after each recalculation

## Step 4: Display in candidate profile

- Add engagement health mini-cards to MESSAGES Tab sidebar (below Memory section):

- Response Rate: 73% (green=>=60%, amber=30-59%, red<30%)

- Avg Response Time: 4.2 hours

- Messages: 18 exchanged

- Sentiment: +0.4 (mostly positive)

## 6B. BUSINESS RULES

▶  Every rule is non-negotiable. If in doubt, escalate to lead BA — never silently skip a rule.

## BR-01: Response Rate Excludes Ghost Periods

When counting response rate, do not count outbound messages sent during a ghosting period (after ghosting detected). These were not responded to because the candidate was formally ghosted — including them would artificially deflate response rate.

↳ Triggered by field: response_rate calculation
