## Why — Business Rationale

- Speciality Engine work is executed through SI partners: PwC, EY, CastleBay, Zensar, LTI Mindtree. Without tagging which SI partner each project runs through, BlitzenX cannot: attribute Speciality revenue correctly, track which SI partner provides the best deployment experience for employees, identify when an employee is already deployed at the same partner a new requirement is coming from (continuity advantage in RM Agent scoring), or report Specialty vs Core revenue split accurately.

## What — Scope

- Add si_partner field to projects table. Mandatory when delivery_engine=SPECIALITY. Dropdown: PwC / EY / CastleBay / Zensar / LTI Mindtree / Other. Used in RM Agent scoring for continuity advantage and in BU Dashboard for SI partner revenue attribution.

## Before — Prerequisites

- HRMS-0253 projects table. HRMS-0255 resource assignments.

## Implementation Steps

## Step 1: Add si_partner to projects table

- ALTER TABLE projects ADD COLUMN si_partner ENUM('PWC','EY','CASTLEBAY','ZENSAR','LTI_MINDTREE','OTHER') nullable.

- Add validation: if delivery_engine=SPECIALITY AND si_partner IS NULL: API returns HTTP 400 'SI Partner is required for Speciality Engine projects.'

- Add to employee_allocations: si_partner copied from project on allocation creation — enables quick lookup of 'who is deployed at PwC right now' without joining to projects.

## Step 2: Build SI partner continuity signal in RM Agent scoring

- In HRMS-0527 RM Agent scoring: if employee's current allocation.si_partner = new demand's si_partner (same partner): apply +5 continuity bonus to composite score. Rationale: an employee already known to the PwC team creates less onboarding friction than someone new to that client environment.

- Continuity bonus labeled in RM recommendation: 'Continuity advantage: already deployed at PwC (+5 score bonus).'

## Business Rules

## BR: SI Partner Mandatory for SPECIALITY Projects

- Projects with delivery_engine=SPECIALITY cannot be saved without si_partner set. Validation at API and UI level. This is not optional context — it is required for revenue attribution and RM Agent scoring.

- Field: si_partner NOT NULL when delivery_engine=SPECIALITY

## BR: SI Partner Copied to Allocation Record

- employee_allocations.si_partner is copied from the project at allocation creation time. This enables fast 'who is at PwC right now' queries without project table joins.

- Field: si_partner denormalised to employee_allocations for query performance
