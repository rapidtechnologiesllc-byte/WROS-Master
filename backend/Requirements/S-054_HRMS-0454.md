## 2. WHY THIS EXISTS

When HR releases an offer to a candidate, the candidate must be notified immediately and professionally. Thunder handles this notification autonomously — sending a warm, personalized message to the candidate explaining that an offer is waiting for them and directing them to the candidate portal to view and respond to it. This is a high-stakes moment in the candidate journey and must be handled with care.

## 3. WHAT YOU ARE BUILDING

Build: (1) trigger that fires when HR marks an offer as released. (2) Thunder sends offer notification via WhatsApp + Email with a warm message and portal link. (3) Conversation state transitions to OFFER_SENT. (4) Offer FAQ Bot is activated for candidate questions.

## 5. STEP-BY-STEP EXECUTION

▶  Follow these steps in exact order. If a step is unclear, ask the lead BA — never assume.

## Step 1: Create offers table

- CREATE TABLE offers: id UUID PK, tenant_id UUID, candidate_id UUID FK→candidates.id, job_id UUID FK→jobs.id, offer_letter_url TEXT (S3 URL), role_title VARCHAR(200), base_salary INTEGER (base currency units), total_compensation INTEGER, start_date DATE, offer_expiry_date DATE, status ENUM('DRAFT','RELEASED','ACCEPTED','DECLINED','EXPIRED','COUNTERED') DEFAULT 'DRAFT', released_at TIMESTAMP nullable, released_by UUID nullable (HR user), candidate_response_at TIMESTAMP nullable, decline_reason TEXT nullable

- Index on (tenant_id, candidate_id, status)

## Step 2: Build releaseOffer() trigger

- When HR user calls PATCH /api/offers/{id}/release (role: HR or Director only):

- Run checkOfferReadiness() one final time. If is_ready=false: return HTTP 409 with blockers.

- UPDATE offers SET status='RELEASED', released_at=NOW(), released_by=hr_user_id

- Publish event: offer.released { candidate_id, offer_id, tenant_id }

- Trigger Thunder notification (Step 3)

## Step 3: Build Thunder offer notification messages

- Load offer details: role_title, base_salary (formatted in candidate's currency), start_date, offer_expiry_date

- Generate WhatsApp message via OFFER_NOTIFICATION prompt: 'Exciting news, [name]! We are pleased to extend a job offer to you for the [Role Title] position at BlitzenX. Your offer includes [salary summary] with a proposed start date of [date]. Please review the full offer in your portal and let us know your decision by [expiry date]. We are excited about the possibility of having you join the team!'

- Email version: same message but HTML-formatted, includes button 'View Your Offer' linking to /candidate/{token}/offer, attaches offer letter PDF if available

- Send BOTH WhatsApp AND Email — this is a critical moment, double channel

- Store in conversation_messages with message_type='OFFER_NOTIFICATION'

## Step 4: Transition state and activate FAQ bot

- Call transitionState(conversation_id, 'OFFER_SENT', 'Offer released by HR', hr_user_id)

- Log conversation_events: OFFER_RELEASED { offer_id, candidate_id, released_by }

- Set a flag on the conversation: offer_faq_active=true (enables HRMS-0455 FAQ Bot to respond to offer questions)

## 6B. BUSINESS RULES

▶  Every rule is non-negotiable. If in doubt, escalate to lead BA — never silently skip a rule.

## BR-01: Readiness Check Runs Again at Release Time

Even if readiness was checked earlier, run checkOfferReadiness() again at the moment PATCH /release is called. Candidate status or interview outcomes could have changed since the initial check.

↳ Triggered by field: checkOfferReadiness() called on every release attempt

## BR-02: Offer Notification Sent on BOTH Channels — Always

Offer notification is sent via both WhatsApp AND email regardless of channel preference. This is a critical decision moment for the candidate. A missed notification here loses a candidate.

↳ Triggered by field: Both channels mandatory for offer notification

## BR-03: Salary Displayed in Candidate's Local Currency Format

The salary in the notification message must be displayed in the candidate's local currency format. India: X LPA. US: $X,000/year. UK: £X,000/year. Never display in base units (paise/cents) to the candidate.

↳ Triggered by field: base_salary display formatting
