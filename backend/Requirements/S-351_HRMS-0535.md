## Why — Business Rationale

- BlitzenX operates two delivery engines — Speciality and Core — with fundamentally different client types, billing rates, compliance requirements, and talent standards. Without a hard system-enforced engine tag on every employee, the two engines bleed into each other: Core resources end up on SI partner subcon work, Speciality resources get placed on direct carrier accounts before they are ready. This story enforces the engine model at the database constraint level — not by policy, by code.

## What — Scope

- Add delivery_engine, engine_entry_date, and core_eligible_from fields to the employees table. Enforce at code level: all new hires enter SPECIALITY — no exceptions. Block any attempt to set CORE on a new hire with HTTP 400. Core can only be set via the Core Eligibility Gate (HRMS-0513) after BU Head approval.

## Before — Prerequisites

- HRMS-0101 employees table. HRMS-0160 convert candidate to employee function.

## Implementation Steps

## Step 1: Add fields to employees table

- ALTER TABLE employees ADD COLUMN delivery_engine ENUM('SPECIALITY','CORE') NOT NULL DEFAULT 'SPECIALITY'.

- ALTER TABLE employees ADD COLUMN engine_entry_date DATE NOT NULL DEFAULT CURRENT_DATE.

- ALTER TABLE employees ADD COLUMN core_eligible_from DATE nullable.

- ALTER TABLE employees ADD COLUMN core_certified BOOLEAN DEFAULT FALSE.

- ALTER TABLE employees ADD COLUMN core_certified_date DATE nullable.

- ALTER TABLE employees ADD COLUMN buddy_program_status ENUM('NOT_STARTED','IN_PROGRESS','GRADUATED','EXTENDED','EXITED') DEFAULT 'NOT_STARTED'.

- ALTER TABLE employees ADD COLUMN buddy_program_start_date DATE nullable.

- ALTER TABLE employees ADD COLUMN buddy_program_graduation_date DATE nullable.

- ADD CHECK CONSTRAINT: delivery_engine cannot be set to CORE unless core_certified=TRUE.

## Step 2: Enforce SPECIALITY on all new hires in convertCandidateToEmployee()

- In HRMS-0160 convertCandidateToEmployee(): always set delivery_engine=SPECIALITY, engine_entry_date=joining_date regardless of any request parameter.

- If API caller passes delivery_engine=CORE: return HTTP 400 'New hires must enter SPECIALITY delivery engine. Core assignment requires Core Eligibility Gate approval (HRMS-0513).'

- Lateral Guidewire hires also enter SPECIALITY first — no exceptions, even for candidates with 10+ years Guidewire experience.

## Step 3: Build engine change audit trail

- Every change to delivery_engine logged in employee_engine_history: employee_id, from_engine, to_engine, changed_at, changed_by, approval_reference (HRMS-0513 gate ID), reason.

- Only HRMS-0513 Core Eligibility Gate can write engine=CORE. No other code path.

## Business Rules

## BR: All New Hires Enter SPECIALITY — Zero Exceptions

- convertCandidateToEmployee() sets delivery_engine=SPECIALITY unconditionally. Database CHECK constraint prevents CORE assignment without core_certified=TRUE. This is enforced at both application and database level — two independent gates.

- Field: delivery_engine=SPECIALITY enforced in code + DB constraint

## BR: CORE Assignment Only Via HRMS-0513 Core Eligibility Gate

- The only code path that can set delivery_engine=CORE is the HRMS-0513 Core Eligibility Gate after BU Head approval. Any direct API call attempting to set CORE without a valid Gate ID returns HTTP 400.

- Field: CORE requires valid Core Eligibility Gate approval reference

## BR: Engine Change Is Permanent and Audited

- Every engine change is written to employee_engine_history with the approving user, timestamp, and gate reference. No change can be made without this audit record. Retroactive changes to engine history are blocked.

- Field: Append-only engine history — no retroactive edits
