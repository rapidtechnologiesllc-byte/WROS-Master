## Why — Business Rationale

- Employee master data, compensation figures, and approved timesheet hours all need to reach whatever payroll system actually runs paychecks — and for a multi-continent operation, that's not one system, it's several, each with its own currency and format expectations. Getting this sync wrong means either a manual re-entry process nobody trusts, or a paycheck error, which is about as high-stakes as a data sync gets.

## What — Scope

- A sync pipeline pushing employee master data, compensation figures (in local currency), and approved timesheet hours to the appropriate continent-specific payroll system.

## Before — Prerequisites

- HRMS-0708 Employee Master base must be live.

- HRMS-0605 TimesheetRevenueProcessor must be producing approved (per R-10) timesheet hours for this sync to push.

## Implementation Steps

## Step 1: Build the continent-based payroll routing

- Each employee's continent (per HRMS-0121) determines which payroll system integration handles their sync.

## Step 2: Build the employee master sync

- Name, employment status, role, compensation — pushed on creation and on any change to these fields.

## Step 3: Build the compensation sync in local currency

- Compensation figures converted from USD-cents storage (per R-09) to the employee's local currency at sync time, matching the same convertFromUSD() display pattern used elsewhere, but for an outbound integration rather than a UI display.

## Step 4: Build the timesheet hours sync

- Only approved hours (per R-10) are ever pushed — an unapproved timesheet never reaches payroll, matching the same hard gate that blocks invoice generation.

## Business Rules

## BR: BR-1308-01 — Only R-10-approved timesheet hours are synced to payroll

- The same rule that blocks invoice generation for unapproved timesheets applies here — payroll must never process hours that haven't cleared internal (and client, where required) approval.

- Field: Timesheet sync query filters on approval_status=APPROVED, identical gate to HRMS-0605's invoice-blocking check

BR: BR-1308-02 — Compensation is converted to local currency only at sync time for display/processing, storage remains USD cents

- Matches R-09 exactly — this is an outbound-integration application of the same rule that governs every other currency display in the platform.

- Field: Payroll sync payload includes a locally-converted figure, but WROS's own storage of compensation remains USD cents throughout

## Integrations

| System / API | Direction | Trigger | Payload | Auth | Notes |
|---|---|---|---|---|---|
| Continent-specific payroll systems | Outbound | On employee master change and per pay period for timesheet hours | employee data, compensation, approved hours | Per-system API credentials | On Failure: sync marked Failed, HR/Finance alerted, retried — a failed payroll sync is treated as urgent, not queued for next cycle |

## Acceptance Criteria

- AC-1: An unapproved timesheet is never included in a payroll sync push.

- AC-2: Compensation figures sync to payroll in the employee's local currency while WROS's own storage remains unchanged USD cents.

- AC-3: A failed sync alerts HR/Finance rather than silently retrying on the standard next cycle.

## Not In Scope

- No payroll calculation logic in WROS itself — this story syncs data to the payroll system, it doesn't compute net pay, taxes, or deductions.
