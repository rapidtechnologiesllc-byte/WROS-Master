## 2. WHY THIS EXISTS

Before an offer letter is generated and sent, the system must verify the candidate is actually eligible and ready. Sending an offer to a candidate who has not completed the interview process, has a compensation mismatch flag, or whose profile shows a red flag wastes everyone's time and creates legal and operational risk.

The Offer Readiness Check is the automated gate between interview completion and offer generation. It protects BlitzenX from premature or erroneous offers.

## 3. WHAT YOU ARE BUILDING

Build checkOfferReadiness(candidate_id, job_id) — a function that validates: interview(s) completed with PASS outcome, no blocking compliance flags, candidate has not withdrawn, compensation score is not critically low. Returns { is_ready: bool, blockers: [] }. Called by HR before generating any offer.

## 5. STEP-BY-STEP EXECUTION

▶  Follow these steps in exact order. If a step is unclear, ask the lead BA — never assume.

## Step 1: Add outcome column to interviews table

- ALTER TABLE interviews ADD COLUMN outcome ENUM('PENDING','PASS','FAIL','NO_SHOW') DEFAULT 'PENDING'

- ALTER TABLE interviews ADD COLUMN outcome_recorded_by UUID nullable (interviewer or HR user who recorded)

- ALTER TABLE interviews ADD COLUMN outcome_recorded_at TIMESTAMP nullable

- This is set by the interviewer feedback system (HRMS-0706 feeds into this)

## Step 2: Build checkOfferReadiness() function

- checkOfferReadiness(candidate_id, job_id, tenant_id) → { is_ready: boolean, blockers: [string], warnings: [string] }

- Check 1 — Candidate status: SELECT status FROM candidates WHERE id=X. If WITHDRAWN or REJECTED: return blocker 'Candidate has withdrawn or been rejected.'

- Check 2 — L1 interview: SELECT * FROM interviews WHERE candidate_id=X AND job_id=Y AND interview_type='L1'. If no record: blocker 'L1 interview not completed.' If outcome='FAIL': blocker 'Candidate failed L1 interview.'

- Check 3 — L2 interview: same for interview_type='L2'. Both L1 and L2 must have outcome='PASS'.

- Check 4 — Compensation flag: SELECT * FROM candidate_job_flags WHERE candidate_id=X AND job_id=Y AND flag_type='COMPENSATION_MISMATCH'. If exists: warning (not blocker) 'Compensation mismatch flagged — review before offering.'

- Check 5 — Experience eligibility: SELECT calculated_experience_months FROM candidates WHERE id=X. If < 60: blocker 'Candidate does not meet 5-year experience requirement.'

- Check 6 — Outstanding compliance flags: any flag_type='COMPLIANCE_BLOCK' from candidate_job_flags: blocker.

- If blockers is empty: return { is_ready: true, blockers: [], warnings: [...any warnings] }

- If blockers exist: return { is_ready: false, blockers: [...], warnings: [...] }

## Step 3: Build GET /api/candidates/{id}/jobs/{job_id}/offer-readiness endpoint

- Auth: HR or Director role only. Recruiter role gets HTTP 403.

- Calls checkOfferReadiness() and returns the result

- Response: { is_ready, blockers: [string array], warnings: [string array], checked_at }

- This endpoint is called by the offer generation UI before displaying the 'Generate Offer' button

## Step 4: Block offer generation if not ready

- In the offer generation flow (HR screen): before showing 'Generate Offer Letter' button, call GET offer-readiness

- If is_ready=false: show blockers as red error items. Hide 'Generate Offer' button. Show 'Resolve Issues First' message.

- If is_ready=true with warnings: show warnings as amber items. Show 'Generate Offer' button (recruiter can override warnings).

- Log conversation_events: OFFER_READINESS_CHECKED { candidate_id, job_id, is_ready, blockers }

## 6B. BUSINESS RULES

▶  Every rule is non-negotiable. If in doubt, escalate to lead BA — never silently skip a rule.

## BR-01: Both L1 AND L2 Must Pass — Not Either

Both interview levels must have outcome='PASS'. L1 PASS + L2 not yet done = blocker. L1 PASS + L2 FAIL = blocker (per HRMS-P608 hard rule). Only L1 PASS + L2 PASS = interview requirement met.

↳ Triggered by field: interviews.outcome for both L1 and L2

## BR-02: Experience Check in Readiness — Belt and Suspenders

The <5yr experience hard rule is enforced at candidate creation (HRMS-P601). But checkOfferReadiness() re-validates it as a final safety check. If somehow an ineligible candidate got through, this check catches it before an offer is sent.

↳ Triggered by field: calculated_experience_months >= 60

## BR-03: Compensation Mismatch Is a Warning, Not a Blocker

A COMPENSATION_MISMATCH flag does not block the offer. The recruiter knows the situation — they may have negotiated a different salary or have budget flexibility. The warning reminds them to verify. Only COMPLIANCE_BLOCK flags are hard blockers.

↳ Triggered by field: COMPENSATION_MISMATCH = warning only
