## 2. WHY THIS EXISTS

A skeleton profile with extracted data is now ready for outreach. The first contact via LinkedIn InMail must be short, specific, and reference something from the candidate's actual LinkedIn profile — not a generic 'We have great opportunities'. Thunder generates personalized InMail messages using the extracted profile data.

This is Thunder's first message to a candidate who has never heard of BlitzenX. First impressions matter enormously here.

## 3. WHAT YOU ARE BUILDING

Build: (1) InMail message generation using INMAIL_OUTREACH prompt. (2) InMail send queue (rate limited). (3) Reply detection. (4) Upgrade from skeleton to active candidate when reply contains contact info.

## 5. STEP-BY-STEP EXECUTION

▶  Follow these steps in exact order. If a step is unclear, ask the lead BA — never assume.

## Step 1: Add INMAIL_OUTREACH prompt to catalog (BA must approve)

- Prompt type: INMAIL_OUTREACH

- System prompt (BA-approved): 'You are writing a LinkedIn InMail from a talent scout at BlitzenX. Write a personalized, concise (100-120 words) InMail message that: (1) Opens with something specific from the candidate's LinkedIn profile (current title, employer, or a skill). (2) Mentions a relevant BlitzenX opportunity concisely. (3) Ends with a soft, non-salesy call to action like asking if they are open to a brief conversation. Do NOT use templates. Do NOT say generic phrases like exciting opportunity. Make it feel like it was written specifically for this person.'

- Additional params: candidate_headline, current_employer, top_skills (from HRMS-P402 extraction), job_title (the BlitzenX opportunity)

## Step 2: Build InMailSendJob (runs twice daily)

- Rate limit: LinkedIn allows typically 25 InMail credits per month per recruiter account. Send max 5 per day per account.

- SELECT QUALIFIED_SKELETON candidates WHERE inmail_status IS NULL AND tenant_id=X ORDER BY technical_score DESC LIMIT 5 (highest score first)

- For each: generateThunderResponse('INMAIL_OUTREACH', candidate_context_with_linkedin_data)

- Send InMail via LinkedIn API or Playwright. Record: UPDATE candidates SET inmail_status='SENT', inmail_sent_at=NOW(), inmail_message_body=generated_text

- Store in conversation_messages: channel=LINKEDIN, direction=OUTBOUND, sender_type=AI

## Step 3: Build InMail reply monitoring

- LinkedInReplyMonitorJob: runs hourly. Checks for InMail replies via LinkedIn messaging API or Playwright.

- When reply detected: store in conversation_messages (channel=LINKEDIN, direction=INBOUND)

- Call HRMS-0433 Intent Detection on the reply

- Publish event: inmail.reply_received { candidate_id, message_body }

## Step 4: Handle reply with contact info — upgrade skeleton

- When InMail reply contains phone or email (detected by HRMS-0422 Facts Extraction):

- Extract phone/email. Call HRMS-P102 upgradeSkeletonProfile(candidate_id, { phone, email })

- This triggers HRMS-0401 ConversationInitializationService — Thunder now has a WhatsApp/email channel and full engagement begins

- Log conversion: UPDATE candidates SET source_conversion='LINKEDIN_INMAIL_TO_WHATSAPP', inmail_status='CONVERTED'

## 6B. BUSINESS RULES

▶  Every rule is non-negotiable. If in doubt, escalate to lead BA — never silently skip a rule.

## BR-01: InMail Must Be Personalized — Never Generic

generateThunderResponse() with INMAIL_OUTREACH prompt must produce a message referencing something specific from the candidate's LinkedIn profile. Validation: message must contain either current employer name or at least one skill from their profile. Fail → regenerate once.

↳ Triggered by field: Personalization validation on InMail

## BR-02: Maximum 5 InMails Per Day Per LinkedIn Account

LinkedIn InMail credits are limited. 5 per day across all outreach from one account. InMailSendJob enforces this strictly. Higher-scored candidates are sent first when daily quota is reached.

↳ Triggered by field: 5 per day per LinkedIn account
