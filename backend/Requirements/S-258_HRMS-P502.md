## Why — Business Rationale

- Finding a Java engineer who's a good bet to become a Guidewire consultant is a different search problem than finding a Guidewire consultant directly — it needs signals a standard keyword search doesn't capture: learning aptitude, genuine interest in switching stacks, and whether the salary gap to market-rate Guidewire work is small enough that the person will actually stick around through training. This engine is what makes HTD sourcing systematic instead of a recruiter's gut feel.

## What — Scope

- A scoring engine that scans the internal DB and LinkedIn for Java developers with 5+ years experience and computes an HTD_readiness score from four weighted signals: Java depth (40%), learning signals (30%), career switch interest (20%), and salary gap vs. Guidewire market rate (10%).

## Before — Prerequisites

- S-257 must be live so this engine knows which requisitions are HTD-track.

- HRMS-P409 LinkedIn Sourcing base must be live for the external search leg.

## Implementation Steps

## Step 1: Build the internal DB scan

- Query existing candidate DB for Java 5+ years, no current Guidewire experience.

## Step 2: Build the LinkedIn scan

- Boolean search generation for Java developers matching the same criteria, reusing the pattern from HRMS-1103 LinkedIn Sourcing Agent Loop where applicable.

## Step 3: Compute java_depth_score and salary_gap_score deterministically

- java_depth_score from years of experience and any listed frameworks/certifications.

- salary_gap_score from comparing the candidate's likely current compensation band to BlitzenX's Guidewire market rate — smaller gap scores higher, since it suggests less flight risk during training.

## Step 4: Call the LLM for learning_signals and career_switch_interest

- Prompt built from available profile text — course completions, side projects, any stated interest in new technologies.

## Step 5: Compute the weighted HTD_readiness score

- HTD_readiness = java_depth×0.40 + learning_signals×0.30 + career_switch_interest×0.20 + salary_gap×0.10.

## Step 6: Surface the ranked list to recruiters

- Sorted by HTD_readiness descending, each with a rationale summary — advisory only, recruiter decides who to actually approach.

## Business Rules

BR: BR-P502-01 — Only learning_signals and career_switch_interest are LLM-scored; java_depth and salary_gap are deterministic

- Keeps the two most auditable, fact-based sub-scores fully explainable without needing to inspect an LLM's reasoning, while still using the LLM where it adds genuine value — reading unstructured profile text.

- Field: java_depth_score and salary_gap_score computed in application code from structured fields only

## BR: BR-P502-02 — This engine is advisory only, no autonomous outreach

- Surfacing and ranking candidates is this story's job; deciding to actually contact them remains a recruiter action, consistent with the platform's graduated-autonomy pattern for anything client- or candidate-facing.

- Field: No sendThunderMessage() or outreach call exists anywhere in this story's scope

## Acceptance Criteria

- AC-1: A Java developer with 6 years experience and strong learning signals scores appropriately higher than one with 5 years and weak signals, verifiable by inspecting the sub-score breakdown.

- AC-2: java_depth_score and salary_gap_score never vary for identical structured input, confirming they're deterministic and not LLM-influenced.

- AC-3: An LLM scoring failure for one candidate does not block the rest of the batch from scoring.
