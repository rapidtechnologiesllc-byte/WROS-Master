## 2. WHY THIS EXISTS

Candidates sometimes need to reschedule after an interview is confirmed — something comes up at work, a personal conflict arises, or the meeting link doesn't work. Thunder handles rescheduling autonomously: the candidate says 'can we move the interview?', Thunder acknowledges, collects new availability, runs calendar matching again, and confirms the new time. No recruiter needed.

## 3. WHAT YOU ARE BUILDING

Build: (1) Detect reschedule intent from candidate message. (2) Acknowledge and collect new availability. (3) Run calendar matching for new slots. (4) Confirm new time. (5) Update Outlook invite. (6) Limit to max 2 reschedules before escalating to recruiter.

## 5. STEP-BY-STEP EXECUTION

▶  Follow these steps in exact order. If a step is unclear, ask the lead BA — never assume.

## Step 1: Add reschedule_count to interviews table

- ALTER TABLE interviews ADD COLUMN reschedule_count INTEGER DEFAULT 0

- ALTER TABLE interviews ADD COLUMN rescheduled_from_interview_id UUID nullable FK→interviews.id

## Step 2: Detect reschedule request and acknowledge

- When HRMS-0433 returns intent=scheduling_request during INTERVIEW_SCHEDULED state:

- Check reschedule_count on current interview. If >= 2: escalate to recruiter instead of rescheduling (see Step 5).

- Thunder sends acknowledgment: 'Of course, no problem! Let me check available times. Could you please share 2-3 alternative time slots that work for you over the next 5 working days?'

- UPDATE interviews.status='RESCHEDULING'. Cancel existing Outlook event via Graph API DELETE /events/{calendar_event_id}.

- Cancel existing interview_reminders (status=CANCELLED).

## Step 3: Collect new availability and run matching

- Clear existing candidate_availability_slots for this candidate (mark expired).

- Thunder collects new availability via HRMS-0447 parseAvailabilityResponse()

- Once 2+ new slots provided: run HRMS-0448 findMatchingSlot() again

## Step 4: Confirm new interview time

- On match found: CREATE new interview record with new scheduled_at_utc, rescheduled_from_interview_id=old interview id, reschedule_count=old_count+1

- UPDATE old interview.status='RESCHEDULED'

- Run HRMS-0449 sendCandidateConfirmation() with new interview record

- New reminders created via HRMS-0450

- Log conversation_events: INTERVIEW_RESCHEDULED { old_interview_id, new_interview_id, reschedule_count }

## Step 5: Escalate after 2 reschedules

- If reschedule_count >= 2 when candidate requests another reschedule: Thunder says 'I have reached out to our recruiting team to assist with your scheduling. Someone will be in touch with you shortly.' Call transitionState() to ESCALATED. Notify recruiter: '[Candidate Name] has requested 3+ reschedules. Please handle scheduling directly.'

## 6B. BUSINESS RULES

▶  Every rule is non-negotiable. If in doubt, escalate to lead BA — never silently skip a rule.

## BR-01: Maximum 2 Reschedules Before Human Escalation

Thunder handles up to 2 interview reschedules autonomously. Third reschedule request: escalate to recruiter. Beyond 2 reschedules, the scheduling difficulty indicates something needing human judgment.

↳ Triggered by field: reschedule_count <= 2

## BR-02: Cancel Existing Outlook Event Before Creating New One

Before creating a new Outlook calendar event for the rescheduled interview: DELETE the existing event using calendar_event_id. Never leave ghost calendar events on the interviewer's calendar.

↳ Triggered by field: calendar_event_id

## BR-03: New Interview Record Created for Each Reschedule

Do not UPDATE the existing interview record with a new time. Create a NEW interview record and mark the old one as RESCHEDULED. This preserves the full scheduling history.

↳ Triggered by field: rescheduled_from_interview_id
