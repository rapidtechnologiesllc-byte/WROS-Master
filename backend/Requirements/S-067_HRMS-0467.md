## 2. WHY THIS EXISTS

After a candidate accepts an offer, the onboarding experience before their first day is critical for retention. A candidate who feels supported and prepared during preboarding is far more likely to show up and stay. Thunder's Onboarding Agent manages the entire preboarding journey — documents, joining instructions, FAQ, first-day logistics — so HR only handles exceptions.

This is where Thunder's value extends beyond recruiting into the employee experience.

## 3. WHAT YOU ARE BUILDING

Build the OnboardingAgent — runs during PREBOARDING state. Coordinates: document collection completion (from HRMS-0457), sends joining instructions at D-7 and D-1, answers joining FAQ questions, confirms start date with candidate, and hands off to HR when all checks complete.

## 5. STEP-BY-STEP EXECUTION

▶  Follow these steps in exact order. If a step is unclear, ask the lead BA — never assume.

## Step 1: Define onboarding touchpoint schedule

- On entering PREBOARDING: immediate — Thunder sends welcome + document request (HRMS-0457 handles this)

- D-7 (7 days before start_date): Thunder sends joining instructions message

- D-3 (3 days before): Thunder sends final preparation checklist

- D-1 (day before): Thunder sends 'See you tomorrow!' message with first-day logistics

- D+1 (day after joining, if employee record created): Thunder sends check-in

- Store as preboarding_touchpoints: { id, candidate_id, touchpoint_type, scheduled_at, status }

## Step 2: Build D-7 joining instructions message

- Load from system_configuration: JOINING_INSTRUCTIONS_D7 template (BA-approved)

- Content (BA must provide): reporting location or remote join link, first-day schedule, point of contact, what to bring, IT setup instructions

- Thunder sends via WhatsApp + Email

- Subject line: '[Your name] — Joining Instructions for [Start Date]'

- Thunder signature included on email

## Step 3: Build D-1 final preparation message

- Thunder sends: 'Hi [name]! Your first day at BlitzenX is tomorrow! Here is a quick summary: [reporting time/link], [first point of contact], [any final instructions]. We are so excited to have you join! See you tomorrow! 🎉'

- Send via WhatsApp + Email

## Step 4: Build onboarding completion check and HR handoff

- OnboardingAgent checks each cycle (via Supervisor): are all documents received AND preboarding_touchpoints all SENT?

- If yes: generate onboarding completion report: { candidate_id, documents_received: [...], touchpoints_completed: [...], joining_readiness_score }

- Notify HR: '[Name] is fully prepared for joining on [date]. All documents received. Preboarding complete.'

- Publish event: onboarding.complete { candidate_id }

- HR takes over for actual day-1 onboarding — Thunder's role ends at this notification

## 6B. BUSINESS RULES

▶  Every rule is non-negotiable. If in doubt, escalate to lead BA — never silently skip a rule.

## BR-01: Onboarding Agent Only Runs in PREBOARDING State

OnboardingAgent is dispatched by Supervisor only when conversation.status=PREBOARDING. If candidate withdraws (status changes to COMPLETED/WITHDRAWN): cancel all pending touchpoints immediately.

↳ Triggered by field: conversation.status=PREBOARDING

## BR-02: D-7 Message Only Sent If Documents Not Yet Complete

If candidate has submitted all documents before D-7: the D-7 message still sends joining instructions but omits the 'please send documents' section. Do not remind about documents that are already received.

↳ Triggered by field: preboarding_documents.status check

## BR-03: HR Handoff Is Final — Thunder Does Not Continue After

After onboarding.complete event is published: Thunder stops all proactive onboarding messages. The candidate is now in HR's hands. If the candidate asks Thunder questions after onboarding.complete: route to HRMS-0055 equivalent FAQ or escalate to HR.

↳ Triggered by field: onboarding.complete event → Thunder stops proactive messages
