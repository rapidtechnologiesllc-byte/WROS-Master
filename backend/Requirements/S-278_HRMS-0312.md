## Why — Business Rationale

- BU Heads need to model 'what if' scenarios before committing to a plan. What if we win 3 deals instead of 2? What if HTD conversion drops to 40%? What if we grow revenue target by 20%? Scenario planning lets BU Heads stress-test their workforce assumptions without affecting the live approved plan.

## What — Scope

- Build scenario planning tool: clone approved plan, adjust parameters (target, win rate, HTD conversion), recalculate demand. Compare up to 3 scenarios side by side.

## Before — Prerequisites

- HRMS-0303 demand plan infrastructure. HRMS-0302 role mapping. HRMS-0304 forecast engine.

## Implementation Steps

## Step 1: Build scenario clone and parameter override

- POST /api/workforce-planning/scenarios: body { plan_id, scenario_name, overrides: { target_amount_usd_cents, htd_conversion_rate_pct, opportunity_win_rate_pct, role_mix_overrides: [{role_type, mix_pct}] } }. Creates workforce_demand_plans record with status=SCENARIO (never activated).

- Run DemandPlanGenerator with overrides applied. Store results as scenario plan items.

## Step 2: Build scenario comparison UI

- Route: /admin/workforce-planning/scenarios

- Select up to 3 scenarios for side-by-side comparison. Table: role_type | Base Plan | Scenario A | Scenario B | difference highlighted.

- Highlight: optimistic (most heads), conservative (fewest), base.

## Business Rules

## BR: Scenarios Cannot Be Approved — They Are Modelling Tools

- SCENARIO status plans never transition to APPROVED. To use a scenario as the live plan: BU Head copies scenario parameters into a new DRAFT plan and approves that. Scenarios are read-only planning models.

- Field: SCENARIO plans non-activatable — modelling only
