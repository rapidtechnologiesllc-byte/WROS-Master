## Why — Business Rationale

- A project sliding toward risk today is usually visible only in hindsight — a missed milestone, a staffing gap, and a cooling client all show up separately, and nobody connects them until the engagement is already in trouble. This agent's job is to combine those already-existing signals into one health_score so a Project Manager sees the pattern the week it starts forming, not the month it becomes a crisis.

## What — Scope

- A daily job that computes a composite health_score per active project from four existing signal sources — milestone status, staffing completeness, timesheet submission consistency, and logged client feedback — and auto-flags any project whose score crosses into AT_RISK or CRITICAL.

## How is Agentic AI Used in This

- This is a monitor-and-flag agent like HRMS-1106 — health_score is computed from a deterministic weighted formula against the four signal sources, not from LLM judgment.

- LLM call (claude-sonnet-4-6, max_tokens=400), used only for projects flagged AT_RISK or CRITICAL: produces a plain-language explanation of which signal(s) are driving the flag, to save the PM from digging through four separate screens.

- All actions are LOW risk (notification only) and auto-execute.

## Before — Prerequisites

- project_milestones table (EPIC-08) must expose on-time/overdue status per milestone.

- HRMS-0605 must expose timesheet submission completeness per project per week.

## Implementation Steps

## Step 1: Create project_health_scores table

- Run CREATE TABLE statement in Data Mapping.

## Step 2: Build the daily composite score job

- Compute four sub-scores (0-100 each): milestone_score, staffing_score, timesheet_score, client_feedback_score.

- health_score = weighted average: milestone 35%, staffing 25%, timesheet 15%, client_feedback 25%.

## Step 3: Classify and generate explanation

- health_score >= 80: HEALTHY. 60-79: WATCH. 40-59: AT_RISK. <40: CRITICAL.

- For AT_RISK/CRITICAL, call LLM with the four sub-scores to generate a plain-language driver summary.

## Step 4: Route notifications

- AT_RISK: HRMS-0113 to assigned PM, daily digest.

- CRITICAL: immediate HRMS-0113 to PM and BU Head.

## Business Rules

## BR: BR-1107-01 — health_score is a deterministic weighted formula

- The formula (35/25/15/25 weighting) is fixed in application code, not learned or LLM-derived — ensures the score is always explainable and reproducible.

- Field: project_health_scores.health_score computed in application code

## BR: BR-1107-02 — CRITICAL always notifies BU Head in addition to PM

- AT_RISK stays within the PM's daily digest; CRITICAL immediately escalates one level to BU Head, matching the escalation pattern in HRMS-1102 and HRMS-1106.

- Field: status=CRITICAL triggers HRMS-0113 to both pm_id and bu_head_id

## Acceptance Criteria

- AC-1: A project with two overdue milestones and understaffing produces a health_score reflecting both factors, verifiable by recomputing the weighted formula manually.

- AC-2: A CRITICAL classification notifies both the PM and BU Head within the same daily cycle.

- AC-3: An AT_RISK classification generates a driver summary referencing the actual lowest sub-score(s).

- AC-4: A missing data source for one day defaults that sub-score to its last known value rather than zeroing the whole health_score.

## Not In Scope

- No LLM-based health scoring — the score itself is a fixed formula; LLM only explains an already-computed score.

- No automatic corrective action (e.g., auto-reassigning staff) — PM and BU Head remain the decision-makers.

- No predictive 'will this project fail' modeling — this is a current-state composite, not a forecast.
