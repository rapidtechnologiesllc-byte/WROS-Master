[Normal] 2. WHY THIS EXISTS
[Normal] Recruiters need to see what Thunder knows about a candidate. If Thunder has extracted that a candidate expects 24 LPA and cannot relocate, the recruiter must be able to see and verify this before making a submission. Without the Memory Viewer, Thunder's knowledge is a black box and recruiters cannot trust it.
[Normal] Recruiters must also be able to correct incorrect facts. If Thunder misunderstood '24 LPA' as '24k USD', the recruiter must be able to fix it manually.
[Normal] 3. WHAT YOU ARE BUILDING
[Normal] Build a Memory Viewer panel in the candidate profile MESSAGES tab sidebar. Shows: the Thunder-generated summary paragraph, then facts organized by category (Salary, Preferences, Constraints, Motivators, Objections, Availability, Skills, Employer). Each fact shows the key, value, confidence indicator, and a correction option.

[Normal] 6B. BUSINESS RULES
[Normal] ▶  Every rule is non-negotiable. If in doubt, escalate to lead BA — never silently skip a rule.
[Normal] BR-01: Manual Corrections Get Full Confidence (1.0)
[Normal] When a recruiter manually corrects a fact value: set confidence=1.0. Manual human corrections are the highest-confidence data in the system. Thunder treats confidence=1.0 facts as verified ground truth in its prompts.
[Normal]   ↳ Triggered by field: confidence
[Normal] BR-02: Low Confidence Facts Shown With Warning
[Normal] Facts with confidence < 0.5 are shown with red dot and a small warning icon. Hovering shows 'Low confidence — verify with candidate before using.' This tells recruiters which facts Thunder is uncertain about.
[Normal]   ↳ Triggered by field: confidence < 0.5
[Normal] BR-03: Fact Corrections Cascade to Candidate Profile
[Normal] If the corrected fact_key maps to a candidate profile field (e.g. expected_ctc → candidates.expected_ctc): the correction must also update the candidates table. This keeps profile data and memory in sync.
[Normal]   ↳ Triggered by field: fact_key → profile field mapping
