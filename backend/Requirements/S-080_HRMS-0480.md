## Step 2: Build production monitoring dashboard

- Route: /admin/thunder-monitoring (ADMIN only)

- Metrics refreshing every 5 minutes for first 2 weeks:

- Error rate: % of Thunder actions resulting in errors in last 1 hour

- SLA compliance: % of new candidates receiving first contact within 60s in last 24h

- WhatsApp delivery rate: % of sent messages confirmed delivered in last 24h

- LLM error rate: % of callLLM() calls failing in last 1 hour

- Supervisor cycle health: last cycle completion time + candidate count

- Active conversations: count by state (QUALIFYING/QUALIFIED/INTERVIEW etc.)

## Step 3: Configure production alerts

- Alert conditions and channels (WhatsApp + email to system admin):

- Error rate > 5% in 15-minute window: CRITICAL alert

- First contact SLA compliance < 90% in last hour: HIGH alert

- WhatsApp delivery rate < 80% in last hour: HIGH alert

- LLM error rate > 10% in 15-minute window: CRITICAL alert

- Supervisor cycle takes > 20 minutes: HIGH alert

- Build alerts using existing HRMS-0113 notification engine pointing to system admin contact

## Step 4: Document rollback plan

- Rollback procedure (if critical issue found post-go-live):

- Step 1: Set tenant_ai_config.thunder_enabled=false (immediate — stops all Thunder actions within 15 min)

- Step 2: Notify all recruiters: 'Thunder has been paused for maintenance. Please handle candidate outreach manually until further notice.'

- Step 3: Investigate root cause with tech lead

- Step 4: Fix, test in staging, re-run affected load test scenarios

- Step 5: Re-enable Thunder with thunder_enabled=true after fix verified

- Document this in /admin/thunder-monitoring as a visible procedure
