## 2. WHY THIS EXISTS

During preboarding, Thunder requests documents via WhatsApp and email. But some candidates prefer uploading documents through a structured portal interface rather than sending files in a chat. The Document Upload page gives them a clear checklist of what's needed and a file upload interface for each document — much more organized than attaching files to WhatsApp.

## 3. WHAT YOU ARE BUILDING

Build the Documents page at /candidate/{token}/documents. Shows the preboarding document checklist with upload buttons per document. Submitted files stored in S3 via HRMS-0457 pipeline. Status updates in real time.

## 5. STEP-BY-STEP EXECUTION

▶  Follow these steps in exact order. If a step is unclear, ask the lead BA — never assume.

## Step 1: Build Documents page

- Route: /candidate/:token/documents

- If no offer accepted yet (conversation.status != PREBOARDING): show 'Document submission will be available after you accept your offer.'

- If PREBOARDING: show full document checklist

- Header: 'Pre-Joining Documents — [X of Y] received'

## Step 2: Build document checklist UI

- For each document in preboarding_documents for this candidate:

- RECEIVED documents: green checkmark ✓ + document name + 'Received [date]'. No upload option.

- PENDING documents: document label + required/optional badge + 'Upload' button

- Clicking Upload: opens file picker. Accept: PDF, DOCX, JPG, PNG. Max 10MB per file.

- On file select: upload to POST /api/portal/candidates/{id}/documents/{document_type} (pre-signed S3 URL or server-side upload)

- On success: document row updates to green ✓ RECEIVED in real time (no page reload needed)

## Step 3: Build document upload API endpoint

- POST /api/portal/candidates/{id}/documents/{document_type} — accepts multipart/form-data file upload

- Auth: candidate session cookie

- Validate: file type (PDF/DOCX/JPG/PNG only). Max 10MB.

- Upload to S3: /candidates/{tenant_id}/{candidate_id}/preboarding/{document_type}/{timestamp}_{filename}

- UPDATE preboarding_documents: status=RECEIVED, document_url=S3_URL, received_at=NOW()

- Publish event preboarding.document_received — same event HRMS-0457 processes

- Response: { status:'RECEIVED', document_type, received_at }

## Step 4: Build completion state

- When all preboarding_documents.status=RECEIVED: show celebration: '🎉 All documents submitted! Our HR team will verify these and be in touch about your joining date.'

- Send notification to HR and recruiter: '[Candidate Name] has submitted all required documents via the portal.'

- This same trigger also comes from Thunder's document collection path (HRMS-0457) — the two paths are unified in the preboarding_documents table

## 6B. BUSINESS RULES

▶  Every rule is non-negotiable. If in doubt, escalate to lead BA — never silently skip a rule.

## BR-01: Document Upload and Thunder Chat Upload Are Unified

Whether a candidate uploads via portal or sends via WhatsApp/email, both paths write to preboarding_documents and publish preboarding.document_received. The HRMS-0457 Document Collection Agent sees both. No duplicate requests after portal upload.

↳ Triggered by field: preboarding_documents unified source of truth

## BR-02: Required vs Optional Documents Both Shown

Required documents are shown first with [Required] badge. Optional documents (if any) shown below with [Optional] badge. The overall completion celebration fires only when all REQUIRED documents are RECEIVED. Optional ones are a bonus.

↳ Triggered by field: is_mandatory flag

## BR-03: 10MB Limit Per File — Enforced at Frontend and Backend

File size check at frontend (before upload) AND at backend API level. A 11MB file must be rejected at both layers with clear error: 'File too large. Maximum 10MB per document.'

↳ Triggered by field: 10MB max per file
