## 2. WHY THIS EXISTS

A recruiter receives a list of 50 Guidewire candidates from a LinkedIn export. They want to start Thunder's engagement campaign for all 50 simultaneously. Currently they would have to create each candidate profile one by one and wait for the automatic trigger. Bulk launch lets them upload a list and start all 50 campaigns in one action — while respecting WhatsApp rate limits to avoid getting the account blocked.

## 3. WHAT YOU ARE BUILDING

Build: (1) Bulk candidate import from CSV. (2) Bulk campaign launch with WhatsApp rate limiting (max 20 messages per minute). (3) Progress tracking UI. (4) Error reporting for failed launches.

## 5. STEP-BY-STEP EXECUTION

▶  Follow these steps in exact order. If a step is unclear, ask the lead BA — never assume.

## Step 1: Build bulk candidate CSV import endpoint

- POST /api/candidates/bulk-import — accepts multipart/form-data with CSV file

- Auth: recruiter auth

- CSV columns: name (required), email, phone, location, current_employer, skills (comma-separated)

- Validate: CSV max 200 rows. Required column 'name' must be present.

- For each row: run dedup check (HRMS-P101 pattern). If exists: skip with note. If new: INSERT candidate.

- Response: { imported: N, skipped_duplicates: N, errors: [{row, reason}], batch_id: UUID }

- batch_id is used to track bulk engagement launch progress

## Step 2: Build bulk engagement launch endpoint

- POST /api/candidates/bulk-engage — body: { candidate_ids: [UUID array], campaign_type: 'STANDARD' }

- OR: POST /api/candidates/bulk-engage-batch — body: { batch_id: UUID } (launch for all imported in a batch)

- Auth: recruiter auth

- Max 200 candidates per bulk launch request

- Create bulk_engagement_jobs record: { id, tenant_id, recruiter_id, total_count, queued_count, success_count, failed_count, status: 'QUEUED' }

- Queue all candidates in a rate-limited job queue. Response: { bulk_job_id, total_candidates, estimated_completion_minutes }

## Step 3: Build BulkEngagementWorker

- Processes the queue at max 20 candidates per minute (WhatsApp rate limit safe default)

- For each candidate: run ConversationInitializationService (HRMS-0401) → creates workspace → sends first WhatsApp + Email

- On success: bulk_engagement_jobs.success_count++

- On failure (WhatsApp blocked, invalid phone): bulk_engagement_jobs.failed_count++. Log to bulk_engagement_errors table.

- After all processed: UPDATE bulk_engagement_jobs.status='COMPLETED'. Notify recruiter via in-app + email: 'Bulk engagement complete: 47 success, 3 failed.'

## Step 4: Build bulk launch progress UI

- Route: /recruiter/bulk-launch

- Two sections:

- IMPORT: CSV upload drag-and-drop zone. 'Import CSV' button. Preview table showing parsed rows. 'Start Import' confirms.

- LAUNCH: After import — 'Launch Thunder for [N] new candidates' button. Progress bar while running. Real-time count: 'Engaged: 23/47'. Completed: summary with links to failed candidates.

## 6B. BUSINESS RULES

▶  Every rule is non-negotiable. If in doubt, escalate to lead BA — never silently skip a rule.

## BR-01: WhatsApp Rate Limit: Max 20 Sends Per Minute

The BulkEngagementWorker processes at most 20 candidates per minute to stay within WhatsApp Business API rate limits. Exceeding this risks account suspension. This rate is configurable in system_configuration: whatsapp_bulk_rate_per_minute (default 20, max 50 for high-tier accounts).

↳ Triggered by field: whatsapp_bulk_rate_per_minute

## BR-02: Dedup Before Engagement — Never Engage Existing Candidates

Before queuing any candidate for bulk engagement: verify they do not already have an active candidate_conversations record. If they do: skip them in the bulk launch (they are already being engaged). This prevents Thunder from sending a second 'greeting' to an existing candidate.

↳ Triggered by field: Existing conversation check before queue

## BR-03: CSV Import Is Separate From Engagement Launch

Importing a CSV and launching engagement are two distinct steps. The recruiter can import, review the preview (including duplicates flagged), correct the list, and THEN launch. Never auto-launch on import.

↳ Triggered by field: Import then review then launch
