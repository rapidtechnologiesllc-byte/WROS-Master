## Why — Business Rationale

- A vendor unsure about a job brief detail today either guesses (and sends the wrong candidates, wasting everyone's time) or emails someone outside the system (and the clarification is lost the moment that email thread ends). A logged, in-portal Q&A keeps every clarification attached to the request permanently, so the next vendor working the same request benefits from the same answer.

## What — Scope

- An in-portal clarification request feature — a vendor asks a question against a specific request, the recruiter is notified and responds within WROS, and the full Q&A thread is logged against the request and visible to the vendor.

## Before — Prerequisites

- S-140 HRMS-P804 must be live — clarification requests are raised against an already-visible open request.

## Implementation Steps

## Step 1: Build the clarification request UI

- From an open request's detail view, vendor submits a question (min 10 chars).

## Step 2: Notify the recruiter

- HRMS-0113 notification to the recruiter who owns the request.

## Step 3: Build the recruiter response flow

- Recruiter responds within WROS — response is visible to the vendor via HRMS-0113 notification and in the request thread.

## Step 4: Log the full Q&A thread

- Every question and answer permanently attached to the request record, visible to any vendor viewing that request going forward — not just the vendor who originally asked.

## Business Rules

## BR: BR-0814-01 — Q&A is visible to all vendors on the request, not just the asker

- A clarification answered once shouldn't need to be asked again by a second vendor working the same request — the thread is a shared resource attached to the request.

- Field: clarification_qa rows are scoped to request_id, queried by any vendor viewing that request

- AC-1: A vendor's clarification question notifies the owning recruiter within the standard HRMS-0113 SLA.
