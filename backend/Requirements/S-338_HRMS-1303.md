## Why — Business Rationale

- LinkedIn sourcing (EPIC-P4, already built) covers proactive, targeted candidate search — but a meaningful share of applicants come from posting a job publicly and letting candidates find it. Different continents have different dominant free job boards, so this needs to be continent-aware from day one rather than US-centric.

## What — Scope

- Auto-publish job requisitions to continent-appropriate free job boards — Indeed and Dice for US, Naukri for India, Reed for UK, Monster for EU — with applicant import and per-channel performance tracking.

## Before — Prerequisites

- HRMS-0701 base Job Requisition creation must be live — this story publishes an existing requisition, it doesn't create one.

## Implementation Steps

## Step 1: Build the continent-based board routing

- Requisition's continent (from HRMS-0121's locale config) determines which board(s) it auto-publishes to.

## Step 2: Build the publish integration per board

- Indeed/Dice (US), Naukri (India), Reed (UK), Monster (EU) — each board's own posting API, standard job fields mapped to each board's schema.

## Step 3: Build applicant import

- Inbound applications from each board mapped into WROS via createCandidateSafe(), same dedup discipline per R-07 as every other candidate entry point.

## Step 4: Build channel performance tracking

- Applications received, quality (interview-to-application ratio), and cost-per-application (where the board charges) tracked per board per requisition.

## Business Rules

## BR: BR-1303-01 — Applicant import uses createCandidateSafe(), no direct inserts

- Per R-07, every candidate entry point — including external job board applicants — goes through the single sanctioned creation path with dedup.

- Field: Job board applicant import calls createCandidateSafe(), same as LinkedIn sourcing and sub-vendor submissions

## Integrations

| System / API | Direction | Trigger | Payload | Auth | Notes |
|---|---|---|---|---|---|
| Indeed/Dice/Naukri/Reed/Monster APIs | Bidirectional | On requisition publish and ongoing applicant polling | job posting fields, applicant data | Per-board API credentials | On Failure: publish retried, applicant import failure for one board doesn't affect others |
| createCandidateSafe() | Outbound | Per imported applicant | applicant fields | Internal | On Failure: applicant import fails for that individual, logged for manual follow-up, doesn't block other applicants in the batch |

## Acceptance Criteria

- AC-1: A requisition tagged with a US continent auto-publishes to Indeed and Dice, not Naukri/Reed/Monster.

- AC-2: Every imported applicant goes through createCandidateSafe(), verified by absence of direct candidate table inserts.

- AC-3: Channel performance tracking accurately reflects applications and interview rate per board.
