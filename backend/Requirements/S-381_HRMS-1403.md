## Why — Business Rationale

- Teams chat is the other half of the daily context-switch problem email solves — a quick question to a colleague, a group discussion about a candidate, currently means leaving WROS entirely. Per Riya's direction, this isn't a tab like email; it behaves like the always-available taskbar presence Teams has on a desktop, reachable from anywhere in WROS without navigating away from whatever screen is currently open.

## What — Scope

- A persistent, collapsible Teams chat dock (in the bottom-dock region S-379 built) that opens a real Teams chat interface without navigating away from the current WROS screen, plus a unified notification center consolidating WROS-native alerts (HRMS-0113) and Teams/Outlook activity in one place.

## Before — Prerequisites

- S-379 must be live — this is the dock framework's primary tenant.

## Implementation Steps

## Step 1: Embed the Teams chat interface in the dock

- Clicking the dock launcher opens an embedded Teams chat view as an overlay/panel — the underlying WROS screen remains visible/accessible behind it, true to the 'taskbar' behavior described.

- Full chat functionality: 1:1, group chats, channels — the real Teams product, not a simplified substitute.

## Step 2: Build document storage routing

- Files shared within an embedded Teams chat follow Teams' native SharePoint storage by default.

- Files uploaded to a WROS entity (candidate resume, invoice, compliance doc) continue using HRMS-0118's existing WROS-native file framework — this story does not change where WROS's own documents live, it only ensures Teams-originated files aren't forced into a redundant second location.

## Step 3: Build the unified notification center

- Consolidates HRMS-0113's existing WROS-native notifications with the Graph webhook bridge from S-379 (new Teams messages, calendar invites) into one notification bell/panel — a user checks one place, not two.

## Business Rules

## BR: BR-1403-01 — Opening the Teams dock never navigates away from the current WROS screen

- This is the defining behavioral requirement from Riya's direction — Teams must behave like a taskbar overlay, not a tab that replaces the current view, or it reintroduces the exact context-switch cost this epic exists to remove.

- Field: Chat overlay renders as a panel/overlay component, not a route change — the underlying WROS screen's state is preserved untouched

BR: BR-1403-02 — WROS's own documents (HRMS-0118) are never redirected into SharePoint by this story

- This story routes Teams-native file sharing to its natural SharePoint home, but does not change where WROS's own candidate/employee/compliance documents are stored — HRMS-0118 remains the single sanctioned framework for WROS-entity file storage.

- Field: No change to HRMS-0118's storage logic; this story only affects files shared inside the embedded Teams chat itself

## BR: BR-1403-03 — The notification center consolidates, it does not duplicate

- A Teams message notification should never also generate a separate, redundant HRMS-0113 alert for the same event — one event, one notification, regardless of source.

- Field: Notification center deduplicates by source event ID before display

## Acceptance Criteria

- AC-1: Opening the Teams dock from any WROS screen does not navigate away from or reload that screen.

- AC-2: A file shared inside an embedded Teams chat lands in its natural SharePoint location, while a document uploaded to a WROS candidate record still uses HRMS-0118's existing framework unchanged.

- AC-3: A single Teams message event produces exactly one notification-center entry, never a duplicate WROS-native alert for the same event.
