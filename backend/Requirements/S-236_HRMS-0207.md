## Why — Business Rationale

- Every revenue number in the Executive Dashboard eventually traces back to an opportunity someone logged. If opportunities are created inconsistently — missing a stage, missing a probability, wrong currency — the forecast built on top of them is fiction dressed up as a number. This is the single entry point that keeps the pipeline data trustworthy from the moment an opportunity is first logged.

## What — Scope

- An Opportunity entity linked to a client, with stage, revenue value in the client's currency, win probability, owner, and expected close date.

## Before — Prerequisites

- S-230 must be live — every opportunity requires an existing client.

## Implementation Steps

## Step 1: Create opportunities table

- Run CREATE TABLE per Data Mapping — client_id, stage, revenue_value, currency, probability_pct, owner_id, expected_close_date.

## Step 2: Build the creation form

- Client lookup, stage dropdown, revenue value entered in the client's default_currency (per S-230), probability, owner, close date.

## Step 3: Store revenue_value in both native currency and converted USD

- Native value entered by the user for their own reference; USD-cents value computed and stored per R-09 for all cross-currency aggregation.

## Business Rules

## BR: BR-0207-01 — Revenue value is captured in client currency but stored in USD cents

- Directly enforces R-09 — the user-facing entry experience uses the client's natural currency, but storage is uniform.

- Field: opportunities.revenue_value_usd_cents is the storage field; revenue_value_native is a display convenience

## Integrations

## Acceptance Criteria

- AC-1: An opportunity entered in a non-USD currency stores an accurate USD-cents equivalent alongside the native value.

- AC-2: An opportunity cannot be created without a valid client_id.

- AC-3: Win probability is constrained to 0-100.
