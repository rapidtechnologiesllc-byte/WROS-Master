## 2. WHY THIS EXISTS

BlitzenX's HARD RULE #1: No candidate with less than 5 years total IT experience can be submitted to a client. This is a fundamental business rule that protects client trust. An ineligible candidate who gets submitted and rejected destroys a client relationship. This gate must be enforced automatically at EVERY submission attempt — regardless of who is submitting or how urgent the demand is.

The only exception: Director + BU Head sequential approval, both required. Even then: logged permanently in audit.

## 3. WHAT YOU ARE BUILDING

Build: (1) checkExperienceEligibility() function — validates 60-month minimum. (2) Hard block on submission API when ineligible. (3) Director override workflow (sequential Director + BU Head). (4) Eligibility status displayed on candidate profile. (5) All eligibility decisions permanently audited.

## 5. STEP-BY-STEP EXECUTION

▶  Follow these steps in exact order. If a step is unclear, ask the lead BA — never assume.

## Step 1: Build checkExperienceEligibility() function

- checkExperienceEligibility(candidate_id, tenant_id) → { is_eligible: boolean, experience_months: integer, deficit_months: integer nullable, status: 'ELIGIBLE'|'INELIGIBLE'|'PENDING_OVERRIDE'|'OVERRIDE_APPROVED' }

- Load candidates.total_experience_months (from HRMS-0428 parsing)

- If total_experience_months >= 60: return { is_eligible: true, status: 'ELIGIBLE' }

- If total_experience_months < 60: return { is_eligible: false, deficit_months: 60 - total_experience_months, status: 'INELIGIBLE' }

- If experience_override_approvals shows DIRECTOR + BU_HEAD both approved: return { is_eligible: true, status: 'OVERRIDE_APPROVED' }

- If null experience (not yet parsed): return { is_eligible: false, status: 'INELIGIBLE', reason: 'EXPERIENCE_NOT_VERIFIED' }

## Step 2: Block submission when ineligible

- In POST /api/submissions (create new submission): call checkExperienceEligibility() first.

- If is_eligible=false AND status != 'OVERRIDE_APPROVED': return HTTP 422 { error: 'EXPERIENCE_INELIGIBLE', message: 'This candidate has [X] months of experience. Minimum required is 60 months (5 years). Deficit: [N] months. A Director + BU Head override is required.', experience_months: X, deficit_months: N }

- Log SUBMISSION_BLOCKED_EXPERIENCE_INELIGIBLE in conversation_audit_log every time this fires.

- UI: disable submission button with tooltip 'Candidate ineligible — [X] months experience. Min 60 required. Request override.'

## Step 3: Build Director + BU Head sequential override workflow

- Create experience_override_approvals table: { id, tenant_id, candidate_id, requested_by, request_reason TEXT (min 200 chars), director_approved_by UUID nullable, director_approved_at TIMESTAMP, director_approval_notes TEXT, bu_head_approved_by UUID nullable, bu_head_approved_at TIMESTAMP, bu_head_approval_notes TEXT, status ENUM('PENDING_DIRECTOR','PENDING_BU_HEAD','APPROVED','REJECTED') }

- Workflow: Recruiter requests override (provides written justification min 200 chars). → Director reviews and approves/rejects. → If Director approves: BU Head receives request. → If BU Head also approves: status=APPROVED. → Now checkExperienceEligibility() returns OVERRIDE_APPROVED.

- BOTH must approve sequentially. Director rejection ends the process.

- Every approval step: log in conversation_audit_log with actor_type=DIRECTOR or BU_HEAD, justification stored.

## Step 4: Build eligibility display on candidate profile

- On candidate profile header: 'Eligibility: ✓ ELIGIBLE (6.2 yrs)' in green OR '✗ INELIGIBLE (4.1 yrs — 11 months short)' in red OR '⚠ OVERRIDE APPROVED by Director + BU Head' in amber

- Red badge cannot be hidden. Recruiter must see this prominently.

- 'Request Override' link shown to recruiters when INELIGIBLE.

## 6B. BUSINESS RULES

▶  Every rule is non-negotiable. If in doubt, escalate to lead BA — never silently skip a rule.

## BR-01: Hard Block — No Bypass Without BOTH Director AND BU Head Override

No recruiter, no HR, no admin can bypass this gate by any means other than the sequential Director + BU Head override process. Even if ADMIN role: submission API blocks without approved override. No code path exists to bypass this check.

↳ Triggered by field: Hard block — no bypass except sequential override

## BR-02: Experience Calculated Using Non-Overlapping Calendar Logic

total_experience_months from HRMS-0428 uses the non-overlapping calculation (overlapping roles counted once). The same candidate cannot inflate their experience by listing simultaneous roles. The 60-month check uses this non-overlapping value, not a simple sum.

↳ Triggered by field: HRMS-0428 non-overlapping calculation is the authoritative source

## BR-03: Override Justification Minimum 200 Characters

The requester must provide substantial written justification for why this ineligible candidate deserves an exception. 'Good candidate' is not sufficient. The justification is permanently stored and audited.

↳ Triggered by field: request_reason min 200 chars

## BR-04: Every Override Request and Decision Permanently Audited

Every step of the override process — request, Director approval/rejection, BU Head approval/rejection — is logged immutably in conversation_audit_log. No override can be made without creating a permanent audit trail.

↳ Triggered by field: conversation_audit_log: immutable override trail
