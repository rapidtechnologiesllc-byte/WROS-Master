## 2. WHY THIS EXISTS

After a candidate accepts an offer, BlitzenX needs several documents before the joining date: ID proof, address proof, last salary slip, experience letters, educational certificates. Chasing candidates for these documents via phone and email is a major HR time sink. Thunder automates the entire collection process — requesting, tracking, reminding, and escalating — without any HR involvement.

## 3. WHAT YOU ARE BUILDING

Build: (1) preboarding_documents table defining required documents per candidate. (2) DocumentCollectionService that creates the checklist on offer acceptance. (3) Thunder requests each document sequentially, tracks receipt, sends reminders every 48h, escalates after 3 missed reminders. (4) Document completion notifies HR.

## 5. STEP-BY-STEP EXECUTION

▶  Follow these steps in exact order. If a step is unclear, ask the lead BA — never assume.

## Step 1: Create preboarding_documents table and populate required docs

- CREATE TABLE preboarding_documents: id UUID PK, tenant_id UUID, candidate_id UUID FK→candidates.id, offer_id UUID FK→offers.id, document_type VARCHAR(100) NOT NULL, document_label VARCHAR(200) NOT NULL, status ENUM('PENDING','RECEIVED','VERIFIED','WAIVED') DEFAULT 'PENDING', document_url TEXT nullable (S3 URL), received_at TIMESTAMP nullable, reminder_count INTEGER DEFAULT 0, last_reminded_at TIMESTAMP nullable, is_mandatory BOOLEAN DEFAULT true

- Required documents (Lead BA must confirm final list): ID_PROOF='Government issued ID (Passport, Aadhar, Driver License)', ADDRESS_PROOF='Proof of current address', LAST_SALARY_SLIP='Most recent salary slip (last 3 months)', EXPERIENCE_LETTERS='Experience/Relieving letters from previous employers', EDUCATION_CERTIFICATES='Highest degree certificate', PAN_CARD='PAN Card (for India candidates only)', BACKGROUND_CHECK_CONSENT='Signed background check consent form'

- On offer.accepted event: INSERT one record per required document for this candidate

## Step 2: Build DocumentCollectionService

- Listens for offer.accepted event

- For each pending document: create preboarding_documents record

- Start document collection sequence: send Thunder's first request message listing all required documents

- Message: 'Welcome to BlitzenX! To complete your joining formalities, I need a few documents from you. Here is what I need: [numbered list of document_labels]. You can share each document directly in this chat as a PDF or image. Let's start with [first document label] — could you share that when you have a moment?'

- Store in conversation_messages as PREBOARDING phase message

## Step 3: Build document receipt detection

- When candidate.document_received event fires (from HRMS-0427): determine document type from filename, context, or HRMS-0431 LLM classification ('What type of document is this? Return one of: ID_PROOF, ADDRESS_PROOF, LAST_SALARY_SLIP, EXPERIENCE_LETTERS, EDUCATION_CERTIFICATES, PAN_CARD, OTHER')

- UPDATE preboarding_documents SET status='RECEIVED', document_url=S3_URL, received_at=NOW()

- Thunder sends acknowledgment: 'Thank you! I have received your [document label]. [If more pending: 'Next, could you share your [next document label]?'. If all received: 'That's everything! Our HR team will verify these and be in touch.']'

- Publish event: preboarding.document_received { candidate_id, document_type }

## Step 4: Build DocumentReminderJob (runs every 6 hours)

- For each PENDING preboarding_documents record where last_reminded_at < NOW() - 48 hours (or last_reminded_at is null and created_at < NOW() - 48 hours):

- If reminder_count < 3: send reminder. UPDATE reminder_count+1, last_reminded_at=NOW(). Thunder: 'Hi [name]! Just a reminder — we still need your [document_label] to complete your joining. Could you please share it at your earliest convenience?'

- If reminder_count >= 3: publish event preboarding.document_overdue { candidate_id, document_type, reminder_count }. Notify HR: '[Name] has not provided [document] after 3 reminders. Please follow up directly.'

## 6B. BUSINESS RULES

▶  Every rule is non-negotiable. If in doubt, escalate to lead BA — never silently skip a rule.

## BR-01: Document Collection Only Runs in PREBOARDING State

DocumentCollectionService and DocumentReminderJob only process candidates in conversation.status=PREBOARDING. If a candidate's status changes (withdrawn, declined) mid-collection: cancel all pending reminder jobs. Do not remind a candidate who is no longer joining.

↳ Triggered by field: conversation.status=PREBOARDING

## BR-02: Country-Specific Documents

PAN_CARD is only required for candidates where candidate.country_code='IN' (India). Do not add it to the checklist for candidates in other countries. The document list must be dynamically built based on candidate country.

↳ Triggered by field: candidate.country_code

## BR-03: 3 Missed Reminders = HR Takes Over

After 3 reminders with no document received: Thunder stops reminding and hands off to HR. Thunder does not send a 4th reminder. HR contacts the candidate directly. This prevents Thunder from nagging candidates so much they reverse their acceptance.

↳ Triggered by field: reminder_count >= 3 → HR takeover
