## 2. WHY THIS EXISTS

Sometimes a recruiter wants to pause Thunder for a specific candidate without fully taking over the conversation. Maybe they want Thunder to stop sending follow-ups for a week while the candidate is on holiday. Or maybe they want to pause Thunder for the entire system temporarily during a company-wide event. Pause & Resume controls give recruiters precise control over Thunder's autonomy at both the candidate level and the system level.

The ownership model (HRMS-0410) handles the case where a recruiter actively takes over. This story handles the 'pause temporarily but let Thunder resume automatically' scenario.

## 3. WHAT YOU ARE BUILDING

Build: (1) Per-candidate pause/resume toggle in MESSAGES Tab. (2) Optional pause duration (pause until date/time). (3) Global system pause toggle for the entire tenant. (4) Automatic resume after pause duration expires.

## 5. STEP-BY-STEP EXECUTION

▶  Follow these steps in exact order. If a step is unclear, ask the lead BA — never assume.

## Step 1: Add pause columns to candidate_conversations

- ALTER TABLE candidate_conversations ADD COLUMN IF NOT EXISTS is_thunder_paused BOOLEAN DEFAULT false

- ALTER TABLE candidate_conversations ADD COLUMN IF NOT EXISTS thunder_paused_at TIMESTAMP nullable

- ALTER TABLE candidate_conversations ADD COLUMN IF NOT EXISTS thunder_resume_at TIMESTAMP nullable (auto-resume when NOW() > this)

- ALTER TABLE candidate_conversations ADD COLUMN IF NOT EXISTS thunder_paused_by UUID nullable (recruiter who paused)

## Step 2: Build pause/resume API endpoints

- POST /api/conversations/{id}/thunder/pause — body: { resume_at: ISO datetime (optional) }. Sets is_thunder_paused=true. If resume_at provided: sets thunder_resume_at. Auth: recruiter.

- POST /api/conversations/{id}/thunder/resume — sets is_thunder_paused=false, clears thunder_resume_at. Auth: recruiter.

- For global tenant pause: PATCH /api/admin/tenant/thunder-enabled { enabled: false/true }. Auth: ADMIN only.

## Step 3: Update Supervisor Agent to check pause flags

- In HRMS-0466 Supervisor Agent state evaluation: before dispatching ANY agent for a candidate: check is_thunder_paused=true. If paused: skip ALL agents for this candidate.

- Also check: global tenant pause (tenant_settings.thunder_enabled). If false: skip ALL candidates.

- Build PauseExpiryJob: runs every 15 minutes. SELECT * FROM candidate_conversations WHERE is_thunder_paused=true AND thunder_resume_at <= NOW(). Auto-resume: UPDATE is_thunder_paused=false, log conversation_events THUNDER_AUTO_RESUMED.

## Step 4: Build UI controls in MESSAGES Tab

- In HRMS-0406 AI Recruiter Status Card: when owner_type=AI: show toggle 'Pause Thunder for this candidate'

- Click shows modal: 'Pause Thunder? For how long? [Resume in: 24h / 48h / 1 week / Until I manually resume]. Confirm | Cancel'

- After pause: Status Card shows 'Thunder: PAUSED until [date]' in amber. Toggle changes to 'Resume Thunder'.

- 'Resume Thunder' click: immediate resume, no confirmation needed.

## 6B. BUSINESS RULES

▶  Every rule is non-negotiable. If in doubt, escalate to lead BA — never silently skip a rule.

## BR-01: Pause Does Not Transfer Ownership

Pausing Thunder (is_thunder_paused=true) does NOT change owner_type. The conversation is still 'owned' by AI in the ownership model. Pause is a separate flag. This means when Thunder resumes, it picks up where it left off without requiring a 'Hand Back' action.

↳ Triggered by field: is_thunder_paused vs owner_type (independent)

## BR-02: Auto-Resume Must Notify Recruiter

When PauseExpiryJob auto-resumes Thunder for a candidate: insert activity feed entry (HRMS-0461): 'Thunder has automatically resumed for [candidate name] — pause duration expired.' Recruiters must know when Thunder re-activates.

↳ Triggered by field: thunder_resume_at auto-resume notification

## BR-03: Global Pause Takes Precedence Over Individual Resume

If tenant.thunder_enabled=false (global pause): even if a candidate's is_thunder_paused=false, Thunder does not act. Global pause overrides all individual settings.

↳ Triggered by field: tenant.thunder_enabled check first
