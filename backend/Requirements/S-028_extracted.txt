[Normal] 2. WHY THIS EXISTS
[Normal] A resume uploaded as a PDF is just a file. The system cannot match it, score it, or act on it until the data is extracted into structured fields. The parsing engine reads the resume and populates: work history, education, skills list, certifications, total experience years, and current employer — all automatically, without recruiter intervention.
[Normal] Critically: the total_experience_years extracted here feeds the <5 year experience hard rule (HRMS-P601). If a candidate's resume shows 4 years 11 months: the system auto-rejects them. The parser must be accurate.
[Normal] 3. WHAT YOU ARE BUILDING
[Normal] Build: (1) Download resume from S3. (2) Extract text from PDF/DOCX. (3) Use LLM to parse structured data. (4) Store structured output in candidate_resume_parsed table. (5) Update candidate profile fields. (6) Calculate total experience in months (critical for <5yr rule).

[Normal] ▶  Follow these steps in exact order. If a step is unclear, ask the lead BA — never assume.
[Normal] Step 1: Create candidate_resume_parsed table
[List Bullet] id UUID PK, tenant_id UUID, candidate_id UUID UNIQUE FK→candidates.id, raw_text TEXT (full extracted text), full_name VARCHAR(200), email VARCHAR(300), phone VARCHAR(50), current_title VARCHAR(200), current_employer VARCHAR(200), work_history JSONB (array of {employer, title, start_date, end_date, description}), education JSONB (array of {institution, degree, field, graduation_year}), skills JSONB (array of skill strings), certifications JSONB (array of {name, issuer, year}), total_experience_months INTEGER, total_experience_years DECIMAL(4,1), languages JSONB, parsed_at TIMESTAMP, parser_version VARCHAR(20)
[List Bullet] Add index on candidate_id
[Normal] Step 2: Build ResumeParsingService that listens to candidate.resume_uploaded
[List Bullet] Download resume PDF/DOCX from S3 URL in the event payload
[List Bullet] For PDF: use pdfminer or PyPDF2 to extract raw text
[List Bullet] For DOCX: use python-docx to extract raw text
[List Bullet] If text extraction fails or produces <100 characters: log RESUME_TEXT_EXTRACTION_FAILED. Publish event parsing.failed. Stop.
[Normal] Step 3: Parse structured data using LLM
[List Bullet] Build parsing prompt: 'You are a resume parser. Extract structured data from this resume text and return ONLY valid JSON with these fields: full_name, email, phone, current_title, current_employer, work_history (array: employer, title, start_date as YYYY-MM, end_date as YYYY-MM or null if current, description), education (array: institution, degree, field, graduation_year), skills (array of strings), certifications (array: name, issuer, year), languages (array of strings). Resume text: [{raw_text}]'
[List Bullet] Call LLM. Parse JSON. Validate: must be valid JSON with at least work_history array present.
[List Bullet] If LLM fails or returns invalid JSON: log RESUME_PARSING_FAILED. Retry once. If both fail: publish parsing.failed event.
[Normal] Step 4: Calculate total experience from work_history
[List Bullet] For each work_history entry: calculate duration in months = (end_date or today) - start_date
[List Bullet] Handle overlapping roles: sort all date ranges, merge overlapping periods, sum non-overlapping duration
[List Bullet] This is CRITICAL: overlapping roles must use MAX not SUM to prevent inflated experience. (A candidate working two jobs simultaneously should not count both toward total experience.)
[List Bullet] total_experience_months = sum of non-overlapping months. total_experience_years = total_experience_months / 12 rounded to 1 decimal.
[List Bullet] Store both in candidate_resume_parsed table AND UPDATE candidates.total_experience_months, candidates.total_experience_years
[Normal] Step 5: Update candidate profile and publish events
[List Bullet] INSERT into candidate_resume_parsed with all parsed fields
[List Bullet] UPDATE candidates: current_employer, skills (JSONB), total_experience_months, total_experience_years, education (JSONB)
[List Bullet] Call markFieldReceived() for: total_experience_years, current_employer, skills (if at least 1 skill found)
[List Bullet] Publish event: candidate.resume_parsed { candidate_id, tenant_id, total_experience_months, skills_count, parsing_success: true }
[List Bullet] HRMS-0429 Skill Extraction and HRMS-P601 Experience Eligibility Engine both listen for this event

[Normal] 6B. BUSINESS RULES
[Normal] ▶  Every rule is non-negotiable. If in doubt, escalate to lead BA — never silently skip a rule.
[Normal] BR-01: Overlapping Roles Use MAX Not SUM — Non-Negotiable
[Normal] If candidate worked at Company A (Jan 2020 - Dec 2022) AND Company B (Jun 2021 - Jun 2023), the overlapping period (Jun 2021 - Dec 2022) is counted once, not twice. Total = Jan 2020 - Dec 2022 + Jan 2023 - Jun 2023 = 3 years. NEVER simple sum of all roles. This rule feeds the <5yr hard rule (HRMS-P601) — an incorrect calculation that inflates experience could allow an ineligible candidate through.
[Normal]   ↳ Triggered by field: work_history date calculation
[Normal] BR-02: Current Role End Date Uses Today
[Normal] If work_history entry has end_date=null (still working there): use today's date as end_date for duration calculation. Recalculate on every re-parse. Do not hardcode a date.
[Normal]   ↳ Triggered by field: work_history.end_date=null
[Normal] BR-03: Parsing Failure Does Not Block Profile
[Normal] If resume parsing fails: log the failure, publish parsing.failed event, mark resume_url as uploaded-but-unparsed. The candidate's profile continues without parsed data. The recruiter is notified to manually review the resume.
