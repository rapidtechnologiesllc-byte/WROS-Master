## 2. WHY THIS EXISTS

Some candidates prefer to fill in their information themselves rather than through a conversation with Thunder. They want to type their salary, location, and notice period into a form — not chat. The Profile Completion Wizard gives candidates this option. They complete their profile once through the portal and Thunder skips asking those questions in future conversations.

Fields filled via the wizard go through the same validation and normalization as Thunder's conversation — the candidate's data is consistent regardless of how it was entered.

## 3. WHAT YOU ARE BUILDING

Build the Profile Completion page at /candidate/{token}/profile. Shows all missing fields as a wizard — one field at a time, or as a full form. Submitted values go through the same HRMS-0426 normalization and call HRMS-0408 markFieldReceived(). Completeness bar updates in real time.

## 5. STEP-BY-STEP EXECUTION

▶  Follow these steps in exact order. If a step is unclear, ask the lead BA — never assume.

## Step 1: Build Profile page with completeness header

- Route: /candidate/:token/profile

- Header: 'Your Profile — [X]% Complete' with green progress bar

- Below bar: '[N] fields left to complete. Thunder uses this information to find the best opportunities for you.'

- API: GET /api/portal/candidates/{id}/profile-status — returns { completeness_score, fields: [{field_name, field_label, status, current_value}] }

## Step 2: Build field input forms for each required field

- Show ONLY fields with status=MISSING. Pre-fill RECEIVED fields as read-only so candidate can see what's already collected.

- Field inputs per type:

- resume: file upload (PDF/DOCX, max 5MB) → HRMS-0427 pipeline

- phone: tel input (international format, E.164 validation)

- notice_period_days: number + unit select (Days/Weeks/Months) — convert to days on save

- current_ctc: number + currency select + period select (Annual/Monthly) — convert to base units on save

- expected_ctc: same as current_ctc

- location: text input with country selector

- current_employer: text input

- total_experience_years: number input (decimal allowed, e.g. 3.5)

- skills: tag input (type skill + Enter to add. Min 1 tag required to submit skills field.)

- email: email input (validate format)

## Step 3: Build field save API endpoint

- PATCH /api/portal/candidates/{id}/fields — body: { field_name: string, raw_value: string|number|array }

- Auth: candidate session token

- For each field: apply normalization (same rules as HRMS-0426):

- notice_period_days: convert weeks/months to days. Validate: integer > 0.

- current_ctc/expected_ctc: convert to base currency units per candidate.country_code. Validate: number > 0.

- On success: call markFieldReceived(candidate_id, field_name, tenant_id). Return { completeness_score, fields_remaining }.

- Response triggers real-time completeness bar update in UI.

## Step 4: Build save-as-you-go UX

- Each field has its own Save button (not one form Save at the end)

- On field save: show green checkmark ✓ on that field. Update progress bar. Show 'Profile [X]% complete — [N] fields left.'

- If Thunder already has this value (status=RECEIVED): show the value with 'Update' link. Update also calls markFieldReceived() with new value.

- On all fields complete: show celebration: '🎉 Your profile is complete! Thunder will be in touch with matching opportunities.'

## 6B. BUSINESS RULES

▶  Every rule is non-negotiable. If in doubt, escalate to lead BA — never silently skip a rule.

## BR-01: Portal Field Values Use Same Normalization as Thunder's Response Parser

Values saved via the portal wizard go through identical normalization as values parsed by HRMS-0426 from conversation messages. '2 months' notice → 60 days. '18 LPA' salary → 1800000 paise. The data model is identical regardless of how the data was entered.

↳ Triggered by field: HRMS-0426 normalization applied to all portal field saves

## BR-02: Completed Fields Shown as Read-Only — Candidate Can Update

Fields already marked RECEIVED are shown with their current value in read-only mode. Candidate can click 'Update' to change them. Update calls the same PATCH endpoint — it is not a separate flow. RECEIVED fields always show so candidate can verify Thunder's extracted values are correct.

↳ Triggered by field: status=RECEIVED → read-only with update link

## BR-03: Resume Upload Triggers Full Parsing Pipeline

When candidate uploads resume via portal: the same HRMS-0427 pipeline runs — download (not needed here, file is direct), store to S3, trigger HRMS-0428 parsing, extract skills via HRMS-0429. All subsequent fields (skills, experience, employer) may auto-fill from the resume.

↳ Triggered by field: Resume upload → full HRMS-0427 pipeline
