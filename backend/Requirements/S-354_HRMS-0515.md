## Why — Business Rationale

- Every employee at BlitzenX needs a continuously updated, LLM-backed performance record that accumulates from Day 1 — not from annual reviews. This store is the single source of truth for: Buddy Program KPI scores, weekly manager inputs, milestone outcomes, client feedback signals, peer survey results, timesheet discipline, interview quality scores, and escalation history. When the AI Assessor (HRMS-0518) evaluates Core eligibility, it reads this store. When the BU Head reviews an employee, they read this store. It must be append-only, immutable, and comprehensive.

## What — Scope

- Build the employee_performance_events table and supporting services. Every KPI input, manager report, milestone event, peer score, and client signal is a row in this table. LLM summarises the trailing 12 weeks on demand. Performance store visible to BU Head, RM, and HR — never to the employee directly.

## Before — Prerequisites

- HRMS-0101 employees. HRMS-0512 engine model.

## Implementation Steps

## Step 1: Create employee_performance_events table

- CREATE TABLE employee_performance_events: id UUID PK, tenant_id UUID, employee_id UUID FK, event_type ENUM('BUDDY_KPI','MANAGER_WEEKLY','MILESTONE_COMPLETED','MILESTONE_OVERDUE','CLIENT_FEEDBACK','PEER_SURVEY','ESCALATION','TIMESHEET_FLAG','INTERVIEW_QUALITY','APPRECIATION','CERTIFICATION_GATE','HR_FLAG') NOT NULL, event_date DATE NOT NULL, score INTEGER nullable (0-100 or 1-5 depending on type), score_category VARCHAR(100) nullable (e.g. 'accountability','technical','adhoc_thinking'), text_notes TEXT nullable, recorded_by UUID nullable (null = system), source_reference_id UUID nullable (FK to buddy_kpi_records, manager_weekly_inputs, etc), created_at TIMESTAMP

- INSERT ONLY — no UPDATE or DELETE at application layer.

- Index: employee_id + event_date for fast performance store queries.

## Step 2: Build PerformanceStoreWriter service

- PerformanceStoreWriter.write(employee_id, event_type, event_date, score, category, notes, recorded_by, source_ref): validates fields, inserts record.

- Called by: HRMS-0516 manager bot, HRMS-0517 milestone tracker, HRMS-0520 buddy KPI system, HRMS-0524 peer survey, HRMS-0523 escalation engine, HRMS-0533 interviewer quality scorer, timesheet late detection job.

- Never called directly from UI — always via source system.

## Step 3: Build LLM performance summary generator

- PerformanceSummaryGenerator.generate(employee_id, weeks=12): reads all events for trailing N weeks. Builds structured prompt: 'Summarise this employee performance record for BlitzenX management review. Identify: strengths, concerns, trajectory (improving/stable/declining), Core readiness signals. Records: [event list]'. Output: { summary_text, trajectory, strengths[], concerns[], core_readiness_signal }.

- Stored in employee_performance_summaries: employee_id, generated_at, week_range, summary_json. Regenerated weekly.

## Step 4: Build performance store API and viewer

- GET /api/employees/{id}/performance: Auth BU Head, RM, HR. Returns: events list (last 90 days), current_summary (latest LLM summary), score_averages per category.

- Performance timeline view: /admin/employees/{id}/performance — chronological event feed with score indicators and category tags.

## Business Rules

## BR: Append-Only — No Retroactive Edits

- employee_performance_events rows can never be updated or deleted after insert. If an error is made: a correction event is logged with event_type=CORRECTION referencing the original event_id. The original record remains permanently.

- Field: INSERT only — no UPDATE/DELETE at application layer. Enforced by DB trigger.

## BR: Performance Store Never Visible to the Employee

- The employee themselves has no access to their own performance store. They see their milestone status (HRMS-0517) and their own timesheet records, but not the manager KPI scores, peer survey responses, or LLM summaries. This is a management intelligence tool, not an employee self-service tool.

- Field: Employee role excluded from GET /api/employees/{id}/performance
