## Why — Business Rationale

- A project without resources assigned to it is just a plan — this is the step that turns a project record into actual staffed delivery, with an allocation percentage and dates precise enough that conflict detection and utilization tracking downstream both work correctly.

## What — Scope

- Resource-to-project assignment with allocation percentage, start/end dates, role, and conflict checking against the employee's existing allocations, plus mapping of the client's own reporting manager for that engagement.

## Before — Prerequisites

- S-299 must be live — assignment happens against an existing project.

- HRMS-0508 Allocation Conflict Detection must be callable.

## Implementation Steps

## Step 1: Build the assignment form

- Employee lookup, allocation percentage (1-100%), start/end date, role on the project.

## Step 2: Wire the conflict check

- Before saving, call HRMS-0508 to confirm the employee's total allocation across all active projects doesn't exceed 100% for the overlapping date range.

## Step 3: Build client reporting manager mapping

- Capture which client-side contact this employee reports to for this specific engagement — used for client-facing status and escalation routing.

## Business Rules

BR: BR-0803-01 — An assignment exceeding 100% total allocation for overlapping dates is blocked

- Prevents accidentally over-committing an employee across simultaneous projects — this is a hard check via HRMS-0508, not just a warning.

- Field: Assignment save blocked if HRMS-0508 conflict check returns a total exceeding 100% for the overlap window

## Acceptance Criteria

- AC-1: An assignment that would push an employee's total overlapping allocation above 100% is blocked before saving.

- AC-2: A successful assignment correctly captures the client reporting manager mapping.
