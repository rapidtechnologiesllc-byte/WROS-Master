## 2. WHY THIS EXISTS

Recruiters need a command center that shows everything they need to act on right now — not a list of 30 candidate profiles to individually open. The Recruiting Dashboard surfaces: AI activity in real time, candidates needing attention, today's interviews, the sourcing pipeline, and SLA breaches — all in one view that a recruiter can scan in 30 seconds.

## 3. WHAT YOU ARE BUILDING

Build the Recruiting Dashboard at /recruiter/dashboard. Six sections: (1) Thunder Activity Live Feed. (2) Intervention Queue summary. (3) Today's Interviews. (4) Pipeline by Stage. (5) Top Candidates by Score. (6) SLA Breach alerts.

## 5. STEP-BY-STEP EXECUTION

▶  Follow these steps in exact order. If a step is unclear, ask the lead BA — never assume.

## Step 1: Build GET /api/recruiter/dashboard endpoint

- Returns all data for the recruiting dashboard in one call. Auth: recruiter auth.

- { thunder_activity_today: { messages_sent, candidates_qualified, interviews_scheduled, escalations }, intervention_queue: { critical_count, high_count, medium_count, top_3_items }, todays_interviews: [{ candidate_name, time_local, level, interviewer }], pipeline: [{ stage, count }], top_candidates: [{ name, overall_score, stage, job_title }] (top 5 by score), sla_breaches: [{ candidate_name, hours_without_contact, breach_type }] }

## Step 2: Build Recruiting Dashboard page

- Route: /recruiter/dashboard. Auth: recruiter auth. Role-mapped by HRMS-P209.

- Layout: 6 cards in a responsive grid (2-col on desktop, 1-col on mobile).

- Card 1 — Thunder Today: 4 mini-metrics: Messages Sent, Qualified, Interviews Booked, Escalations (all since midnight today)

- Card 2 — Needs Attention: [CRITICAL: N] [HIGH: N] [MEDIUM: N] counts. 'View Queue' button → HRMS-0462

- Card 3 — Today's Interviews: list of interviews today with candidate name, time in recruiter timezone, L1/L2 badge, interviewer name

- Card 4 — Pipeline by Stage: horizontal bar showing count per stage (QUALIFYING / QUALIFIED / INTERVIEW / OFFER / PREBOARDING)

- Card 5 — Top Candidates: table of top 5 by overall_score with name, score bar, stage, job

- Card 6 — SLA Breaches: list of candidates with breach type and hours since last contact. Link to each candidate profile.

## Step 3: Auto-refresh mechanism

- Dashboard auto-refreshes every 5 minutes via simple interval + GET dashboard endpoint.

- Manual refresh button (↺) in header. Shows 'Last updated: X minutes ago'.

## 6B. BUSINESS RULES

▶  Every rule is non-negotiable. If in doubt, escalate to lead BA — never silently skip a rule.

## BR-01: Dashboard Shows Only This Recruiter's Tenant Data

All data is filtered by tenant_id from the recruiter's session. Cross-tenant data never shown.

↳ Triggered by field: tenant_id filter always

## BR-02: Pipeline Stage Counts Exclude COMPLETED and WITHDRAWN

Pipeline counts only include active candidates (not COMPLETED, WITHDRAWN, MERGED). The pipeline card must show only candidates actively being worked.

↳ Triggered by field: Active candidates only in pipeline
