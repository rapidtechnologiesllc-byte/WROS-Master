## 2. WHY THIS EXISTS

When Thunder sends a WhatsApp message asking the candidate to upload their resume or view their offer, the candidate must be able to tap once and land directly in the right page of their portal — pre-authenticated. Zero friction. If the candidate has to copy a link, open a browser, sign in, and navigate: most of them won't bother.

## 3. WHAT YOU ARE BUILDING

Build: (1) Deep link generation with target page encoding. (2) Include magic link + deep link target in every relevant Thunder WhatsApp message. (3) Link router that handles the deep link parameter and navigates to the correct page after auth.

## 5. STEP-BY-STEP EXECUTION

▶  Follow these steps in exact order. If a step is unclear, ask the lead BA — never assume.

## Step 1: Build deep link URL format

- URL format: https://{portal_domain}/candidate/{magic_token}?go={page}

- page values: home, messages, profile, interview, offer, documents

- generateDeepLink(candidate_id, tenant_id, target_page) → { url, token }

- Calls generateMagicLink() internally, appends ?go={target_page} to URL

## Step 2: Wire deep links into Thunder WhatsApp messages

- Thunder automatically includes a deep link in specific messages:

- After sending resume request: '...You can also upload it directly here: {deep_link_to_profile}'

- After offer release: '...View and respond to your offer here: {deep_link_to_offer}'

- After interview confirmation: '...View your interview details and add to calendar here: {deep_link_to_interview}'

- Links generated per candidate using their current valid magic token (or generating new one if expired)

- Links included in template using {{portal_link}} variable — template must include this variable for relevant template keys

## Step 3: Build deep link router in portal

- On /candidate/{token}?go={page}: after token validation and session creation, redirect to /candidate/portal/{page}

- If page param missing or invalid: redirect to /home (default)

- Log portal_deep_link_used event: { candidate_id, target_page, created_at }

## 6B. BUSINESS RULES

▶  Every rule is non-negotiable. If in doubt, escalate to lead BA — never silently skip a rule.

## BR-01: Deep Link Uses Existing Valid Token If Available

Before generating a new magic token for a deep link: check if candidate already has a valid (non-expired, non-revoked) token. If yes: use that token in the deep link. Only generate a new token if none exists. This preserves the 7-day window the candidate already has.

↳ Triggered by field: Reuse existing valid token when possible

## BR-02: Deep Link in WhatsApp — Not Raw URL

WhatsApp auto-previews URLs. The deep link URL must be short enough to not dominate the message. Consider URL shortening if the full URL is over 60 characters. The portal domain should be configured as short as possible (e.g. portal.blitzenx.com).

↳ Triggered by field: URL length consideration
