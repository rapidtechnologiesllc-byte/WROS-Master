## Why — Business Rationale

- 90 billable Specialty days is the minimum proof point that an employee can operate in a client environment without creating risk. The clock is simple in concept but the implementation must handle real-world complexity: what happens when the clock resets on a resource-error escalation? What if the employee goes on bench mid-clock? What if they switch Specialty clients? The clock must track billable days only — not calendar days, not bench days, not onboarding days.

## What — Scope

- Build the 90-day billable Specialty certification clock. Tracks from first billable day after Buddy graduation. Counts only approved billable timesheet days. Resets on RESOURCE_ERROR escalation. Pauses on bench. Reaches CERTIFIED at 90 days clean. Status visible to BU Head and RM.

## Before — Prerequisites

- HRMS-0521 buddy graduation (SPECIALITY_READY). HRMS-0507 allocations. HRMS-0605 timesheet revenue (billable day confirmation). HRMS-0523 escalation engine.

## Implementation Steps

## Step 1: Create specialty_certification_clocks table

- CREATE TABLE specialty_certification_clocks: id UUID PK, tenant_id UUID, employee_id UUID UNIQUE FK, clock_type ENUM('STANDARD_90','HTD_365'), clock_start_date DATE nullable (set on first billable day), billable_days_count INTEGER DEFAULT 0, reset_count INTEGER DEFAULT 0, last_reset_date DATE nullable, last_reset_reason TEXT nullable, status ENUM('NOT_STARTED','RUNNING','PAUSED_BENCH','CERTIFIED','RESET'), certified_date DATE nullable.

## Step 2: Build billable day counter

- Daily job: for each employee with clock status=RUNNING: check if any approved timesheet hours for yesterday. If yes: billable_days_count += 1. If billable_days_count >= 90 (or 365 for HTD): set status=CERTIFIED, certified_date=YESTERDAY. Notify RM and BU Head.

- If employee goes to bench (no allocation): status=PAUSED_BENCH. billable_days_count does not increment. Resumes on next allocation.

## Step 3: Build clock reset on RESOURCE_ERROR escalation

- HRMS-0523 escalation engine calls ClockResetHandler.reset(employee_id, reason) when escalation_type=RESOURCE_ERROR is confirmed.

- Reset: billable_days_count=0, status=RUNNING, reset_count+=1, last_reset_date=TODAY, last_reset_reason=reason.

- Notify RM and BU Head: 'Specialty Certification Clock RESET for [name]. Reason: [escalation summary]. Reset count: [N]. Clock restarts from today.'

- Second reset: BU Head must log a performance note before clock resumes.

## Business Rules

## BR: Clock Counts Billable Days Only — Not Calendar Days

- The clock increments only when the daily job confirms approved timesheet hours for that day. A weekend, a bench day, a sick day, or a public holiday does not increment the counter. 90 billable days may take 4-5 calendar months depending on project cadence.

- Field: Billable days only — approved timesheets are the gate

## BR: RESOURCE_ERROR Reset Is Immediate and Non-Negotiable

- When HRMS-0523 confirms escalation_type=RESOURCE_ERROR: ClockResetHandler.reset() fires immediately. RM and BU Head are notified before the employee. The clock resets to zero. There is no appeal process for the reset — the investigation (HRMS-0523) determines the type. If the type is confirmed RESOURCE_ERROR, the clock resets. End of discussion.

- Field: RESOURCE_ERROR: immediate clock reset. No override.

## Acceptance Criteria

- AC-1: Clock starts on first approved billable day after Buddy graduation

- AC-2: Only approved billable days increment the counter

- AC-3: CERTIFIED at 90 days — RM and BU Head notified

- AC-4: RESOURCE_ERROR escalation resets clock to zero immediately

- AC-5: Bench period pauses clock — resumes on next allocation

- AC-6: Second reset requires BU Head performance note before resume
