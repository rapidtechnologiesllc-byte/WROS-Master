## Why — Business Rationale

- Originally scoped as a full real-time 'agent' analysing Thunder performance and HTD conversion continuously, this capability was re-scoped after review: nothing about analysing weekly/monthly trend data needs to happen in real time, and there is no action for it to autonomously take — its entire output is a report that informs human decisions later. Building full agent scaffolding (trigger cadence, action-intent events, escalation thresholds) around a report generator added complexity with no corresponding benefit. It is now a scheduled weekly batch job, which is simpler to build, test, and trust.

## What — Scope

- A weekly batch job that analyses Thunder conversation outcomes, AI candidate-ranking accuracy (against actual placement outcomes), and HTD conversion trend data, and produces a structured improvement-signal report for the Director and BU Heads — it takes no autonomous action of any kind.

## How is Agentic AI Used in This

- This is explicitly NOT a real-time autonomous agent. It runs once weekly (Monday 04:00) as a batch job, with no action-intent events published and no entry in the Orchestration Router's conflict table, because it performs no state-changing action.

- LLM call (claude-sonnet-4-6, max_tokens=1200, the one exception to the platform's default 1000-token cap, justified by the volume of trend data being synthesised): given a week's worth of Thunder outcome data, ranking-vs-placement accuracy data, and HTD conversion numbers, produces a structured report with named improvement signals and supporting evidence.

- Output is advisory-only, consumed by humans in the weekly ops review — no downstream automation acts on this report's conclusions without a human first deciding to implement a change.

## Before — Prerequisites

- HRMS-1102 through HRMS-1108 must have at least 4 weeks of historical event data for the first report to be statistically meaningful — do not run this job in the first month of EPIC-11 going live.

## Implementation Steps

## Step 1: Create learning_optimisation_reports table

- Run CREATE TABLE statement in Data Mapping.

## Step 2: Build the weekly data aggregation

- Pull Thunder conversation outcomes (response rate, qualification rate, drop-off points) for the trailing week.

- Pull AI candidate-ranking scores and cross-reference against actual placement outcomes from submissions table.

- Pull HTD conversion numbers from HRMS-P509.

## Step 3: Generate the improvement-signal report

- Call LLM with the aggregated dataset.

- Structure output: {thunder_signals[], ranking_accuracy_signals[], htd_signals[], overall_summary}.

- Store full report in learning_optimisation_reports.

## Step 4: Distribute

- Send via HRMS-0113 to Director and all BU Heads as part of the standing weekly ops review packet.

- No auto-action taken on any signal in the report.

## Business Rules

## BR: BR-1109-01 — No autonomous action of any kind

- This job never writes to any operational table besides its own report table — it is read-only against all source systems.

- Field: learning_optimisation_reports is the only table this job writes to

## BR: BR-1109-02 — Not included in Orchestration Router conflict monitoring

- Because it takes no action, it publishes no agent.action.intent events and has no conflict_rules entries — this is a deliberate simplification, not an oversight.

- Field: HRMS-1109 absent from conflict_rules entity_type enum

## Acceptance Criteria

- AC-1: The job runs exactly once weekly and produces exactly one report row per week.

- AC-2: The report writes to no table other than learning_optimisation_reports — verified by code review.

- AC-3: A source-data outage causes the job to skip and log the gap rather than generate a partial or misleading report.

- AC-4: The report is delivered to Director and all BU Heads within the same day it is generated.

## Not In Scope

- No real-time triggering, no action-intent events, no Orchestration Router integration — this is deliberately a simple batch job.

- No automatic implementation of any suggested improvement — every signal requires a human decision to act.

- No per-conversation or per-candidate granular output — this is a weekly aggregate report, not a case-by-case audit.

## How to Demo to End User
