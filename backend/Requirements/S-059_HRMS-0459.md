## 2. WHY THIS EXISTS

A recruiter managing 30 candidates across different stages needs to see at a glance where everyone is in the pipeline. Currently they must open each candidate profile individually. The Journey Dashboard provides a visual stage-by-stage pipeline view — every candidate shown at their current stage, with key metrics visible without clicking into the profile.

## 3. WHAT YOU ARE BUILDING

Build a visual stage-tracker component on the candidate profile showing their journey: Engaged → Qualifying → Screened → Interview → Offer → Preboarding → Joined. The current stage is highlighted. Each stage shows date entered and key metrics. Clicking a stage navigates to the relevant tab or detail.

## 5. STEP-BY-STEP EXECUTION

▶  Follow these steps in exact order. If a step is unclear, ask the lead BA — never assume.

## Step 1: Define journey stages and their data mappings

- Stage 1 — ENGAGED: entered when INITIATED→QUALIFYING transition. Shows: date engaged, channel (WhatsApp/Email), response time to first message.

- Stage 2 — QUALIFYING: entered on QUALIFYING state. Shows: profile completeness %, days in stage, Thunder's qualification messages count.

- Stage 3 — SCREENED: entered on QUALIFIED state. Shows: overall score, date qualified, missing fields (if any remaining).

- Stage 4 — INTERVIEW: entered on INTERVIEW_SCHEDULING or INTERVIEW_SCHEDULED state. Shows: L1 status (scheduled/passed/failed), L2 status, interview date(s).

- Stage 5 — OFFER: entered on OFFER_SENT state. Shows: offer sent date, expiry date, candidate decision (pending/accepted/declined/countered).

- Stage 6 — PREBOARDING: entered on PREBOARDING state. Shows: joining readiness score, documents received count, days until start.

- Stage 7 — JOINED: entered on COMPLETED state with reason='JOINED'. Shows: joining date, employee ID (from HRMS-0708).

## Step 2: Build GET /api/candidates/{id}/journey endpoint

- Auth: recruiter auth, tenant_id filter

- Load: conversation_state_history (all transitions), current state, stage-specific data per reached stage

- Response: { stages: [{stage_name, stage_label, status ('completed'|'active'|'pending'), entered_at nullable, exited_at nullable, metrics: {key: value} }], current_stage, candidate_id }

## Step 3: Build CandidateJourney React component

- File: src/components/candidate/CandidateJourney.jsx

- Props: { candidateId }

- Fetches GET /api/candidates/{id}/journey on load

- Renders a horizontal step-tracker: [Engaged] → [Qualifying] → [Screened] → [Interview] → [Offer] → [Preboarding] → [Joined]

- Each stage: circle icon (✓ completed = green, ● active = blue animated pulse, ○ pending = gray). Stage label below. Date entered below label.

- Active stage shows its metrics in a card below the tracker

- Clicking a completed stage: shows that stage's metrics in the card and deep-links to relevant section (e.g. clicking Interview → navigates to interview tab on profile)

- Component placed at top of candidate profile page, above the tab navigation

## Step 4: Show active stage metrics card

- When a stage is active (current stage): show a card below the tracker with stage-specific metrics

- QUALIFYING: '72% complete — 3 fields still missing. Days in qualifying: 4. Thunder has sent 8 messages.'

- SCREENED: 'Overall Score: 87/100. Technical: 92 | Compensation: 100 | Availability: 75.'

- INTERVIEW: 'L1: Passed (Jan 18). L2: Scheduled for Jan 22, 2PM CST.'

- OFFER: 'Offer sent Jan 20. Expires Jan 27. Status: Awaiting decision.'

- PREBOARDING: 'Joining Readiness: 73%. 4 of 6 documents received. Joining Feb 1.'

## 6B. BUSINESS RULES

▶  Every rule is non-negotiable. If in doubt, escalate to lead BA — never silently skip a rule.

## BR-01: Journey Shows Historical Stages Even if Candidate Returns to Earlier Stage

If a candidate goes QUALIFIED → ESCALATED → QUALIFYING again (re-qualification after escalation): the tracker shows all stages visited, with multiple entries for the same stage. It is a history, not just a current position.

↳ Triggered by field: conversation_state_history

## BR-02: JOINED Stage Only Shown After HRMS-0708 Converts Candidate to Employee

The final JOINED stage only turns green when HRMS-0708 (Convert Candidate to Employee) runs. Before that, even if the candidate is in PREBOARDING, JOINED stage shows as gray/pending.

↳ Triggered by field: JOINED stage condition
