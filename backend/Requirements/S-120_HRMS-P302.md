## 2. WHY THIS EXISTS

Generic nurture messages are better than nothing. Desire-driven personalized messages are dramatically better. When HRMS-P118 knows a candidate's top desire is CAREER_GROWTH, Thunder doesn't send 'We have exciting opportunities' — it sends 'John, I thought you'd want to know that 3 of our Guidewire consultants got promoted to Principal Architect in 2024. BlitzenX invests heavily in technical career progression — something I know matters to you.'

This story upgrades the nurture campaign messages to be fully desire-profile-driven when a desire profile is available.

## 3. WHAT YOU ARE BUILDING

Build desire-profile-aware message generation for all nurture touchpoints. When desire_profile exists: override standard NURTURE template with a PERSONALIZED_VALUE prompt that uses top_desire_category + content library to craft highly targeted messages.

## 5. STEP-BY-STEP EXECUTION

▶  Follow these steps in exact order. If a step is unclear, ask the lead BA — never assume.

## Step 1: Build generatePersonalizedValueMessage() function

- generatePersonalizedValueMessage(candidate_id, tenant_id, touchpoint_number) → message text

- Load desire_profile. Load motivation content library for top_desire_category (shared with HRMS-P119).

- If no desire_profile: fall back to standard NURTURE prompt (HRMS-P301 behavior).

- Build PERSONALIZED_VALUE prompt: 'You are Thunder, Talent Scout at BlitzenX. Write a nurture message (touchpoint {N} of 4, scheduled {days} days after last contact) for this candidate. Their top career desire is {top_desire_category} (score: {score}). Choose ONE approved fact from the content library and craft a message that: (1) references something specific from their background or previous conversation, (2) connects that BlitzenX fact to THIS candidate's specific desire, (3) ends with a soft, non-pushy touch. Approved facts: {content_library}. Candidate memory: {memory_summary}. IMPORTANT: Never say the candidate told you about their desires — make the connection feel natural and observational, not like you are reading back their profile to them.'

- Validate: message must reference candidate name AND at least one library fact.

## Step 2: Wire into NurtureCampaignJob

- In NurtureCampaignJob (HRMS-P301): before generating touchpoint message:

- Call generatePersonalizedValueMessage() if desire_profile exists

- If desire_profile missing: call standard generateThunderResponse() with NURTURE prompt

- This upgrade is seamless — same touchpoint schedule, better messages.

## Step 3: Build message quality validation

- After generation: run validation checks:

- Must contain candidate's first name: scan for name string

- Must contain content library fact substring: scan message against library items

- Must be 50-300 characters (short enough for WhatsApp, long enough to be meaningful)

- If any check fails: regenerate once. If second attempt also fails: log PERSONALIZED_MSG_FAILED, send standard NURTURE message instead.

## 6B. BUSINESS RULES

▶  Every rule is non-negotiable. If in doubt, escalate to lead BA — never silently skip a rule.

## BR-01: Library Facts Only — Never Fabricated Statistics

generatePersonalizedValueMessage() shares the same content library constraint as HRMS-P119. Thunder uses ONLY approved BA-signed-off facts. The validation check confirms a library string is present in the generated message.

↳ Triggered by field: Content library validation on every personalized message

## BR-02: Desire Profile Required for Personalization — Fallback to Standard

If no desire_profile: standard NURTURE message (HRMS-P301). If desire_profile exists but confidence is low (<0.6 top desire score): also use standard NURTURE. Only high-confidence desire profiles drive personalized messages.

↳ Triggered by field: top_desire_score >= 0.6 required for personalization
