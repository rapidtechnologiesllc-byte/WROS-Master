## 2. WHY THIS EXISTS

HRMS-P605 enforced the no-market-profile rule at the candidate level (before conversion to employee). This story extends the same rule to the employee side: once someone is an employee, their submission eligibility depends on their employee status — only BENCH or ALLOCATED employees are submittable. An employee on notice, on leave, or in pre-joining cannot be submitted to a new client.

## 3. WHAT YOU ARE BUILDING

Extend HRMS-0711 submission pipeline to check employee status when the submitted candidate has been converted (has a linked employees record). Add employee-level eligibility to the submission compliance gate sequence.

## Step 1: Build checkEmployeeSubmissionEligibility()

- checkEmployeeSubmissionEligibility(candidate_id, tenant_id) → { eligible: boolean, employee_id nullable, employee_status nullable, reason: string }

- Check if employees record exists with candidate_id=X (has this candidate been converted to employee?)

- If no employee record: return { eligible: true } — still a candidate, checked by HRMS-P605 instead

- If employee record found: check employees.status

- ELIGIBLE statuses: BENCH, ALLOCATED (being lined up for next project)

- INELIGIBLE: PRE_JOINING (not yet started), ON_LEAVE, NOTICE_PERIOD, EXITED

- Return { eligible, employee_status, employee_id, reason }

## Step 2: Wire to submission pipeline

- In POST /api/submissions: after HRMS-P601/P605/P606 checks, add this check as step 4:

- If employee record found AND status not BENCH/ALLOCATED: HTTP 422 { error: 'EMPLOYEE_STATUS_INELIGIBLE', message: 'This employee is currently [status] and cannot be submitted. Only BENCH or ALLOCATED employees can be submitted to clients.', employee_status }

- This check supersedes HRMS-P605 for converted employees (they have an employee status, not just a candidate status).

## BR-01: Employee Status Check Supersedes Candidate Status for Converted Employees

Once a candidate has been converted to an employee (employees record exists), their submission eligibility is determined by employees.status (this story) rather than candidates.status (HRMS-P605). The employee record is the authoritative status for converted candidates.

↳ Triggered by field: employees.status is authoritative for converted candidates
