## 2. WHY THIS EXISTS

The candidate portal home is the first thing a candidate sees when they tap Thunder's link. It must immediately communicate: where they are in the process, what actions they need to take, and that BlitzenX values their time. A confusing or empty home screen loses candidate trust instantly.

The home dashboard is the candidate-facing equivalent of the recruiter's MESSAGES tab — a command center for the candidate's own experience with BlitzenX.

## 3. WHAT YOU ARE BUILDING

Build the candidate portal home dashboard at /candidate/{token}/home. Shows: (1) Personalized welcome with Thunder's identity. (2) Current stage badge. (3) Pending actions (what the candidate needs to do). (4) Recent messages preview. (5) Navigation to other portal sections. Mobile-first, single column.

## 5. STEP-BY-STEP EXECUTION

▶  Follow these steps in exact order. If a step is unclear, ask the lead BA — never assume.

## Step 1: Build portal route structure and navigation

- Route: /candidate/:token — validates token, establishes session, redirects to /candidate/:token/home

- Navigation tabs (bottom on mobile, top on desktop): Home | Messages | Profile | Interview | Offer (only shown when relevant)

- 'Offer' tab only visible when conversation.status=OFFER_SENT or PREBOARDING

- 'Interview' tab only visible when interview record exists for this candidate

## Step 2: Build Home Dashboard page

- Welcome card: '⚡ Hi [First Name]! I'm Thunder, your talent scout at BlitzenX — Powering our global team at lightning speed. Here's where things stand.'

- Stage progress bar: linear stages: [Applied] → [Qualifying] → [Screened] → [Interview] → [Offer] → [Joined]. Current stage highlighted.

- Pending Actions card: list of things the candidate needs to do right now. Examples: 'Upload your resume', 'Reply to Thunder's message about your notice period', 'Confirm your interview time', 'Review your offer'. Each action is a tappable link to the right page.

- Recent Messages card: last 3 messages from Thunder, newest first. Each shows: Thunder icon, message preview (first 60 chars), timestamp. 'View all messages' link.

- Quick Stats row (small): '72% profile complete | Next: Notice Period | Thunder sent 8 messages'

## Step 3: Build GET /api/portal/candidates/{id}/home-summary API

- Auth: candidate session token

- Returns all data needed for home dashboard in one call:

- { candidate: { first_name, completeness_score }, conversation: { status, state_label }, pending_actions: [{type, label, url_path, urgency}], recent_messages: [{direction, message_body_preview, channel, sent_at}] (last 3), interview_upcoming: { scheduled_at, interviewer_name, format } nullable, offer_status: 'RELEASED'|'ACCEPTED'|null }

- Pending actions logic: if resume_url=null → add 'Upload your resume'. If any inbound Thunder message unread → 'Reply to Thunder'. If interview unconfirmed → 'Confirm your interview'. If offer=RELEASED → 'Review your offer'.

## Step 4: Build mobile-first responsive layout

- Single column on mobile (375px+). Max-width 600px centered on desktop.

- All touch targets minimum 48px height

- No horizontal scrolling at any width

- Thunder's name and BlitzenX logo in header. Logout option in header (invalidates magic link session).

## 6B. BUSINESS RULES

▶  Every rule is non-negotiable. If in doubt, escalate to lead BA — never silently skip a rule.

## BR-01: Thunder Identity Always From Assignment — Never Hardcoded

The welcome message always uses candidate_ai_assignment.ai_agent_name ('Thunder') and never has the name hardcoded. If BlitzenX ever renames their AI recruiter, one config change updates the portal immediately.

↳ Triggered by field: candidate_ai_assignment.ai_agent_name

## BR-02: Pending Actions Must Show Highest Priority First

Pending actions are sorted by urgency: HIGH (offer pending, interview unconfirmed) first, MEDIUM (resume missing) second, LOW (reply requested) third. The most important action must be immediately visible without scrolling.

↳ Triggered by field: pending_actions sorted by urgency

## BR-03: Portal Must Load in Under 3 Seconds on Mobile

Candidates access this on mobile, often on slow connections. Home dashboard must make a single API call (GET home-summary). All section data in one response. Target: visible content in under 3 seconds on 3G connection.

↳ Triggered by field: single API call performance target
