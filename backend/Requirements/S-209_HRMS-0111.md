## Why — Business Rationale

- Every role in Section 12 sees a different slice of WROS. Without one shell that adapts its menu and search scope to who's logged in, every team either sees options they can't use or has to remember a different URL for every module. And a recruiter who can't quickly find a candidate by name across every channel loses time on every single call — search isn't a nice-to-have, it's the difference between Thunder-speed and spreadsheet-speed.

## What — Scope

- A single navigation shell — collapsible sidebar with role-scoped menu items, mobile-responsive — plus a global search bar that queries across candidates, clients, opportunities, jobs, and employees in one box, scoped to the user's active BU context and role.

## Before — Prerequisites

- HRMS-0103 RBAC must expose a queryable list of menu permissions per role.

- HRMS-0107 BU Context Switching must be live so search results scope correctly.

## Implementation Steps

## Step 1: Build the sidebar shell

- Collapsible, persists collapsed/expanded state per user.

- Menu items rendered from a role-permission lookup, not hardcoded per role — new roles don't require a frontend redeploy.

## Step 2: Build the global search index

- Full-text index across candidates.name, clients.name, opportunities.title, jobs.title, employees.name.

- Continent-aware: results respect the active BU context, never leak across tenants (per HRMS-0109).

## Step 3: Build the search UI

- Single input, results grouped by entity type, keyboard-navigable.

- Debounced query, results update as-you-type after 2+ characters.

## Step 4: Mobile-responsive collapse

- Sidebar collapses to a hamburger menu below tablet breakpoint.

- Search remains a persistent top-bar element at every breakpoint.

## Business Rules

## BR: BR-0111-01 — Menu items are permission-driven, never hardcoded by role name

- Adding a new role or changing a role's permissions updates the visible menu automatically — no frontend code change required.

- Field: Sidebar renders from RBAC permission query, not a role==X conditional

## BR: BR-0111-02 — Search results never cross tenant or unauthorized BU boundaries

- Search queries pass through the same tenant/BU scoping middleware as every other query — search is not a backdoor around HRMS-0109.

- Field: Search index queries are wrapped by the same scoped query builder as all other endpoints

## Acceptance Criteria

- AC-1: A user's sidebar shows only menu items their role is permitted to access, verified across at least 3 distinct roles.

- AC-2: Search results never include entities outside the user's tenant or active BU, verified with a cross-tenant test query.

- AC-3: Sidebar collapses to a hamburger menu below the tablet breakpoint without loss of functionality.

- AC-4: Search returns grouped, entity-typed results within 300ms of the debounce window closing.

## Not In Scope

- No AI-powered semantic search in this story — standard full-text indexing only; semantic search is a future AI Intelligence Layer story if ever needed.

- No customizable/user-configurable menu ordering — menu structure is role-driven, not user-driven.
