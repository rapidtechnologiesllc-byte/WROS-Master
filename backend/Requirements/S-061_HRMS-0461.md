## 2. WHY THIS EXISTS

A recruiter managing 30 active candidates with Thunder running autonomously needs a live feed of what Thunder is doing — right now. 'Thunder sent a follow-up to John. Thunder qualified Sarah. Thunder detected a ghosting risk on Mike.' Without this feed, Thunder is a black box. Recruiters cannot supervise, trust, or adjust its behavior.

The Activity Feed is the recruiter's window into Thunder's autonomous operations. It is the transparency mechanism that makes human-AI collaboration work.

## 3. WHAT YOU ARE BUILDING

Build: (1) thunder_activity_feed table aggregating all Thunder actions. (2) Real-time activity feed UI in the recruiter dashboard. (3) Per-candidate activity view in the Messages Tab. (4) Global feed showing all candidates Thunder is working on simultaneously.

## 5. STEP-BY-STEP EXECUTION

▶  Follow these steps in exact order. If a step is unclear, ask the lead BA — never assume.

## Step 1: Create thunder_activity_feed table

- CREATE TABLE thunder_activity_feed: id UUID PK, tenant_id UUID, candidate_id UUID, candidate_name VARCHAR(200), activity_type VARCHAR(100), activity_summary TEXT (1-2 sentences, human-readable), activity_data JSONB (structured details), severity ENUM('INFO','WARNING','ACTION_REQUIRED') default 'INFO', is_read BOOLEAN default false, created_at TIMESTAMP

- Index on (tenant_id, created_at DESC), (tenant_id, candidate_id, created_at DESC)

- Populated by: ActivityFeedPublisher service (Step 2)

## Step 2: Build ActivityFeedPublisher service

- Listens for all key internal events and creates feed entries:

- message.received → 'Thunder received a reply from [Name] on WhatsApp. They answered about their notice period.'

- conversation.state_changed → 'Thunder moved [Name] from Qualifying to Qualified. Profile is 100% complete.'

- candidate.ghosted → 'Thunder detected [Name] has not responded after 3 follow-ups. Marked as ghosted.'

- sla.breach_detected → 'SLA breach: [Name] has not been contacted in 27 hours.' (severity=WARNING)

- candidate.high_abandonment_risk → '[Name] has a 78% abandonment risk. Review recommended.' (severity=ACTION_REQUIRED)

- interview.confirmed → 'Thunder scheduled [Name] for L1 interview with [Interviewer] on [date].'

- offer.released → 'Offer released to [Name] for [Role]. Awaiting their decision.'

- ESCALATION_TRIGGERED → 'Thunder escalated [Name] — [reason]. Human review required.' (severity=ACTION_REQUIRED)

- For each event: INSERT into thunder_activity_feed with human-readable summary

## Step 3: Build GET /api/activity-feed endpoint

- GET /api/activity-feed?candidate_id={optional}&severity={optional}&page=1&per_page=25

- Auth: recruiter auth. Filter by tenant_id always.

- If candidate_id provided: return feed for that candidate only (for Messages Tab view)

- If no candidate_id: return global feed across all candidates (for recruiter dashboard)

- ORDER BY created_at DESC

- Response: { activities: [...], total_count, unread_count, has_more }

- Each activity: { id, candidate_id, candidate_name, activity_type, activity_summary, severity, is_read, created_at }

- PATCH /api/activity-feed/{id}/read — marks single activity as read

- PATCH /api/activity-feed/read-all — marks all activities as read for this recruiter's view

## Step 4: Build Activity Feed UI components

- GLOBAL FEED: In recruiter dashboard header — bell icon with unread count badge. Click opens slide-out panel with full activity feed. Each item: colored left border (INFO=gray, WARNING=amber, ACTION_REQUIRED=red), candidate name + action summary, relative time. Click navigates to candidate MESSAGES tab.

- PER-CANDIDATE FEED: In candidate MESSAGES Tab — add 'Thunder Activity' section below Missing Fields widget in the right sidebar. Shows last 10 Thunder actions for this candidate. Auto-refreshes every 30 seconds.

## 6B. BUSINESS RULES

▶  Every rule is non-negotiable. If in doubt, escalate to lead BA — never silently skip a rule.

## BR-01: ACTION_REQUIRED Items Are Never Auto-Marked Read

INFO and WARNING items auto-mark as read when the recruiter opens the feed panel. ACTION_REQUIRED items must be manually marked read by the recruiter. They remain highlighted until explicitly dismissed. A recruiter must consciously acknowledge each escalation or high-risk alert.

↳ Triggered by field: severity=ACTION_REQUIRED

## BR-02: Feed Retains 30 Days of History

Activities older than 30 days are archived (not deleted). The feed UI shows last 30 days by default. Archived entries still accessible via export.

↳ Triggered by field: created_at retention
