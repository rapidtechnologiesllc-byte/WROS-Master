## Why — Business Rationale

- The performance intelligence store is only as good as the data going into it. Manager memory fades, annual reviews miss nuance, and ad-hoc feedback is inconsistent. The weekly input bot contacts every reporting manager every Friday at 4pm and collects a structured performance report for every employee they manage. Small consistent signals — 5 questions, 10 minutes — build an accurate picture over months that no single review can match.

## What — Scope

- Build the Friday weekly manager input bot: WhatsApp-based conversational bot contacts reporting manager, collects 6 structured inputs per employee, writes to performance store. Non-response logged as gap. One reminder after 24h. BU Head alerted if manager misses 3 consecutive weeks.

## Before — Prerequisites

- HRMS-0515 performance store. employees.reporting_manager_user_id. WhatsApp Business API configured. HRMS-0113 notifications.

## Implementation Steps

## Step 1: Build WeeklyInputBot scheduler

- Every Friday at 4pm local BU time: for each active employee (status not EXITED): find reporting_manager_user_id. Send WhatsApp message to manager's registered number.

- Message format: 'BlitzenX Weekly Team Check-In 📋
For: [Employee Name] — Week ending [date]
1. Accountability (1-5): Did they take ownership this week?
2. Requirements Understanding (1-5): Did they grasp what was asked?
3. Development Signal (1-5): Growing, stable, or regressing?
4. Stories/Tasks Completed: [number]
5. Client Feedback: Positive / Neutral / Concern
6. Any notes? (optional, reply or skip)
Reply with 6 answers e.g: 4,5,4,8,Positive,Good week'

## Step 2: Build response parser and performance store writer

- Parse WhatsApp reply: extract 6 values. Validate: scores 1-5, completed integer, feedback enum. On valid: call PerformanceStoreWriter.write() for each scored dimension as separate events with event_type=MANAGER_WEEKLY.

- On invalid format: send one clarification message: 'Format not recognised. Please reply: [accountability],[requirements],[development],[stories_count],[positive/neutral/concern],[optional notes]'

- On no response by Saturday 4pm: send one reminder. On no response by Sunday 4pm: log event_type=MANAGER_WEEKLY with score=NULL, notes='No response Week [N]'. Alert RM.

## Step 3: Build non-response escalation

- If manager misses 3 consecutive weekly inputs for same employee: notify BU Head. BU Head must log reason (manager unavailable, employee on leave, etc). If no BU Head response in 24h: flag in HRMS-0536 BU Dashboard as data gap.

## Business Rules

## BR: One Report Per Employee Per Week — No Backfilling

- The bot collects exactly one report per employee per week. Managers cannot submit late reports for prior weeks via bot. If a week is missed: it is logged as a gap permanently. This maintains data integrity — backdated positive inputs cannot manipulate historical performance records.

- Field: No backfill — one report per week per employee, no exceptions

## BR: Manager Non-Response Is a Performance Signal for the Manager

- A reporting manager who consistently fails to submit weekly inputs is itself a management accountability signal. After 3 consecutive misses: BU Head is alerted. This is tracked in the manager's own profile, not just the employee's record.

- Field: Manager non-response tracked against manager's own accountability record
