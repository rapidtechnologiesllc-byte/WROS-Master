## Why — Business Rationale

- Revenue forecast adjustment, project delay prediction, and margin prediction are financially-adjacent questions with a shared shape: given historical patterns, what's likely to happen to a number that matters. Keeping this cluster as one engine — separate from the talent-signal engine in S-306 — respects a real boundary: financial predictions carry different sensitivity and different consumers (Finance, BU Heads) than talent predictions (RMs, recruiters), so they stay in their own configuration group even though the underlying framework pattern is the same.

## What — Scope

- A second prediction engine, structurally similar to S-306 but scoped to financial signals: (1) auto-adjust the deterministic weighted forecast (S-238) using pipeline velocity, historical win rates, seasonal patterns, and continent trends, (2) predict project delivery delay risk from milestone and staffing signals, (3) predict margin trend for active projects from cost and utilization signals.

## Before — Prerequisites

- S-238 HRMS-0209 must be live — the revenue-forecast-adjustment config is explicitly an overlay on its output, not an independent calculation.

- At least 2-3 quarters of historical pipeline and project delivery data should exist for meaningful predictions — early low-confidence output should be visible via the same confidence_pct pattern as S-306, not hidden.

## Implementation Steps

## Step 1: Build the revenue-forecast-adjustment configuration

- Input: S-238's deterministic weighted forecast + pipeline velocity trend + historical win rates by BU/continent + seasonal pattern data.

- Output: an adjusted forecast figure presented ALONGSIDE the deterministic baseline, never overwriting it — both figures visible on S-241's Executive Dashboard, clearly labeled.

## Step 2: Build the delay-risk configuration

- Input: current milestone status and staffing-gap signals (reusing S-302 and S-303 data), historical patterns of similar projects.

- Output: delay_risk_pct, surfaced on the project detail view alongside S-305's risk flagging, not as a competing separate score.

## Step 3: Build the margin-trend configuration

- Input: S-304's rough margin indicator history + utilization trend for allocated resources.

- Output: margin_trend_direction (Improving/Stable/Declining) with rationale.

## Business Rules

BR: BR-1004-01 — The AI-adjusted forecast is always shown alongside, never instead of, the deterministic S-238 figure

- S-238's weighted forecast is the auditable baseline the Executive Dashboard and Forecast vs Actual comparison depend on — this story adds an advisory overlay, it does not become the new baseline.

- Field: S-241's dashboard displays both figures with explicit labels, never substitutes one for the other

BR: BR-1004-02 — No automatic budget, pricing, or project-status action based on any financial prediction

- Matches S-306's BR-1001-01 guardrail applied to the financial domain — these are Finance/BU Head decision-support signals, not autonomous financial actions.

- Field: No prediction output here has a write path to project budgets, billing rates, or project status fields
