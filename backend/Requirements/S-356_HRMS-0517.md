## Why — Business Rationale

- Milestones are the objective, system-generated complement to the subjective manager ratings. A manager might rate an employee 4/5 on delivery — but did they actually complete their milestones on time? Milestone completion or failure is a fact, not an opinion. This story builds the three-tier milestone system: personal goals set at onboarding, project delivery checkpoints, and org-level targets aligned to the BU. All outcomes auto-write to the performance store.

## What — Scope

- Build project_milestones table supporting three types: PERSONAL, PROJECT, ORG. PERSONAL and PROJECT completions auto-write to HRMS-0515 performance store. OVERDUE detection runs nightly. PM and RM notified on overdue.

## Before — Prerequisites

- HRMS-0515 performance store. HRMS-0253 project entity. HRMS-0101 employees.

## Implementation Steps

## Step 1: Create project_milestones table

- CREATE TABLE project_milestones: id UUID PK, tenant_id UUID, project_id UUID FK nullable (null for PERSONAL/ORG), employee_id UUID FK nullable (null for PROJECT-level), milestone_type ENUM('PROJECT','PERSONAL','ORG'), title VARCHAR(300), description TEXT, target_date DATE, completed_date DATE nullable, status ENUM('PENDING','IN_PROGRESS','COMPLETED','OVERDUE','CANCELLED','EXTENDED'), completion_notes TEXT nullable, set_by UUID, created_at TIMESTAMP.

## Step 2: Build OVERDUE nightly detection

- Nightly job: UPDATE project_milestones SET status=OVERDUE WHERE target_date < CURRENT_DATE AND status IN ('PENDING','IN_PROGRESS').

- On OVERDUE detected: (a) write performance event via PerformanceStoreWriter (event_type=MILESTONE_OVERDUE, employee_id, notes=milestone title). (b) Notify PM and RM.

## Step 3: Build milestone completion auto-write to performance store

- On PATCH /api/milestones/{id}/complete: set status=COMPLETED, completed_date=TODAY. If milestone_type in (PERSONAL, PROJECT) and employee_id set: call PerformanceStoreWriter(event_type=MILESTONE_COMPLETED, score=100 if on time else 70 if late, notes).

- On time completion scores higher than late completion — both are positive but punctuality matters.

## Business Rules

## BR: PERSONAL Milestone OVERDUE Reduces Core Eligibility Score

- Every OVERDUE personal milestone writes a performance event that the AI Assessor (HRMS-0518) treats as a negative signal. Consistently missed personal milestones are a strong indicator that the employee lacks the self-management required for Core carrier work.

- Field: OVERDUE = performance event = AI assessor signal

## BR: Milestone Completion Is System-Recorded — Cannot Be Backdated

- completed_date is set to CURRENT_DATE at the moment of the completion API call. It cannot be manually set to a past date. This prevents gaming the system by marking milestones complete retroactively to improve scores.

- Field: completed_date = CURRENT_DATE on API call — no manual date entry
