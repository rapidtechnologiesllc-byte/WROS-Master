## Why — Business Rationale

- An HTD job posting and a standard lateral Guidewire hire posting need genuinely different criteria — HTD explicitly does NOT require Guidewire experience and instead weighs Java depth and learning aptitude, while a standard posting requires the opposite. Without an explicit HTD job track, recruiters end up manually remembering which rules apply to which requisition, which is exactly the kind of judgment call this platform exists to remove.

## What — Scope

- A job posting configuration that tags a requisition TRACK=HTD, switching its evaluation criteria to Java depth (required), Guidewire experience (explicitly not required), and learning aptitude — full-time only, per R-03.

## Before — Prerequisites

- HRMS-0701 base Job Requisition creation must be live — this story adds a track type on top of it.

## Implementation Steps

## Step 1: Add TRACK field to job requisitions

- Enum: STANDARD / HTD. Default STANDARD.

## Step 2: Build the HTD-specific criteria set

- When TRACK=HTD: Guidewire experience field is hidden/not required, Java years-of-experience becomes a required field (5+ per HTD's platform-wide minimum), learning aptitude assessment flag added.

## Step 3: Enforce FT-only for HTD track

- HTD requisitions cannot be posted with any employment type other than FULL_TIME, per R-03 — same enforcement pattern as HRMS-P806's sub-vendor gate, applied here at requisition creation instead of submission.

## Business Rules

## BR: BR-P501-01 — HTD track requisitions cannot require Guidewire experience

- This is the defining characteristic of the HTD program — requiring Guidewire experience on an HTD requisition would defeat its purpose of training non-Guidewire engineers.

- Field: Guidewire experience field is not rendered and not stored for TRACK=HTD requisitions

## BR: BR-P501-02 — HTD track is full-time only, no exceptions

- Matches R-03's platform-wide rule, enforced at the requisition level for HTD specifically since it's the entry point to a long training investment that only makes sense for a full-time hire.

- Field: employment_type field locked to FULL_TIME when TRACK=HTD, not just defaulted

## Acceptance Criteria

- AC-1: An HTD-track requisition does not display or store a Guidewire experience requirement.

- AC-2: An HTD-track requisition cannot be saved with an employment_type other than FULL_TIME.

- AC-3: A Java experience field appears and is required only when TRACK=HTD.

## Not In Scope

- No automatic conversion of a STANDARD requisition to HTD or vice versa — track is set once at creation, changing it requires creating a new requisition.
