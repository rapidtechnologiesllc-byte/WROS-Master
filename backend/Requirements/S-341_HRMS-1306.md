## 2. WHY THIS EXISTS

HRMS-0448 Calendar Matching needs to read interviewer free/busy data from Outlook to find matching slots. HRMS-0449 Interview Confirmation needs to create calendar events in the interviewer's Outlook. Both require a properly configured, authenticated Microsoft Graph API integration with tenant-level OAuth2 setup.

## 3. WHAT YOU ARE BUILDING

Build: (1) Microsoft Azure AD app registration and OAuth2 configuration. (2) Token management (access token refresh, tenant-level service account). (3) getFreeBusy() function. (4) createCalendarEvent() function. (5) deleteCalendarEvent() function. (6) Admin configuration UI for Outlook credentials.

## 5. STEP-BY-STEP EXECUTION

▶  Follow these steps in exact order. If a step is unclear, ask the lead BA — never assume.

## Step 1: Build Outlook OAuth2 token management

- Store per-tenant Microsoft credentials in tenant_integrations table: { id, tenant_id, integration_type='OUTLOOK', client_id, client_secret (encrypted), tenant_azure_id, access_token (encrypted), refresh_token (encrypted), token_expires_at }

- Build refreshOutlookToken(tenant_id): checks token_expires_at — if expiring within 5 minutes: call Microsoft identity platform to refresh. Store new access_token and token_expires_at.

- Build getOutlookToken(tenant_id): returns valid access_token (refreshing if needed). All Microsoft Graph calls use this.

## Step 2: Build getFreeBusy() function

- getFreeBusy(user_email, date_from, date_to, tenant_id) → array of { start_utc, end_utc, status: 'BUSY'|'FREE'|'TENTATIVE' }

- Call Microsoft Graph: POST /users/{user_email}/getSchedule with scheduleInformation array.

- Parse response: extract busy periods within business hours (09:00-17:00 interviewer timezone).

- Return free slots by inverting busy periods within the business hours window.

## Step 3: Build createCalendarEvent() function

- createCalendarEvent(user_email, event_details, tenant_id) → { event_id, calendar_event_url }

- event_details: { subject, start_utc, end_utc, body, attendees: [{email, name}], location }

- Call Microsoft Graph: POST /users/{user_email}/events

- Return event_id (stored as interviews.calendar_event_id for future updates/cancellations).

## Step 4: Build updateCalendarEvent() and deleteCalendarEvent() functions

- updateCalendarEvent(user_email, event_id, updates, tenant_id): PATCH /users/{user_email}/events/{event_id}

- deleteCalendarEvent(user_email, event_id, tenant_id): DELETE /users/{user_email}/events/{event_id}

- Both needed for HRMS-0451 reschedule and any cancellation flows.

## Step 5: Build admin Outlook configuration UI

- Route: /admin/integrations/outlook. ADMIN only.

- Form: Azure App Client ID, Client Secret (masked input), Azure Tenant ID.

- [Test Connection] button: calls Microsoft Graph to verify credentials work.

- Save stores encrypted credentials in tenant_integrations.

## 6B. BUSINESS RULES

▶  Every rule is non-negotiable. If in doubt, escalate to lead BA — never silently skip a rule.

## BR-01: Credentials Stored Encrypted — Application Level

Microsoft client_secret, access_token, and refresh_token stored with AES-256 encryption. Never plaintext in DB or logs. Decrypted only in memory during API calls.

↳ Triggered by field: Encrypted credential storage

## BR-02: Token Auto-Refresh 5 Minutes Before Expiry

getOutlookToken() proactively refreshes the token when it expires within 5 minutes. Never allow an API call to fail due to expired token when the refresh could have been done proactively.

↳ Triggered by field: 5-minute pre-expiry refresh window

## BR-03: Graph API Failure Triggers Fallback Email + Admin Alert

If Microsoft Graph API fails (CAPTCHA, throttling, auth error): log OUTLOOK_API_FAILED. Fall back to sending email to interviewer. Alert admin. Do not crash interview scheduling.

↳ Triggered by field: Email fallback on API failure
