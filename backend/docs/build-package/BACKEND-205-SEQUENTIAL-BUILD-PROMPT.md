## Per-story workflow (from the Phase-4 prompt, reused — vertical slices only)

For each story, in order:

1. **Verify real current state** — `git log --oneline` + grep `CLAUDE.md` session log for this WROS-ID (and any drifted alias) before assuming nothing exists.
2. Read the real requirement `.docx` via python-docx (not a summary) — confirm the WROS-ID against the canonical sheet if the filename looks off (known drift pattern, see CLAUDE.md/memory).
3. Build/extend backend (models, services, migration) only if genuinely missing.
4. Build the REST API layer wired to the service.
5. Build the frontend screen/panel.
6. **Verify it actually works in the browser** with the preview tools — real click-through, not "the code compiles." Screenshot or describe what was seen.
7. Write/extend tests — service-level AND API-level (FastAPI `TestClient`).
8. Run the **full** backend suite, confirm green, no regressions.
9. Commit and push — backend and frontend separately, both directly to `main`, small logical units.
10. **Stop. Present the finished story to Avinash — what was built, how it was verified, screenshot/proof — and wait for explicit approval.**
11. Only after approval: mark the row `Done` in `WROS_Canonical_Backlog_S001-401.xlsx` with a `Change Log` entry, then move to the next story in the list.

Do not start story N+1's build work while story N is awaiting approval. One story in flight at a time, per Avinash's explicit gating instruction.
