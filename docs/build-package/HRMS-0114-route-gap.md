dependency. Some of these likely already have SOME authentication via
`Depends(get_current_candidate)` / `Depends(get_current_hr_or_admin)` /
`Depends(get_current_internal_user)` — those gate on "is this a logged-in
candidate/user at all," which is a real and valid check, just not the
granular RBAC permission HRMS-0114 asks for. Others may have no auth
dependency at all. **Check each one individually before assuming its
current risk level** — don't treat this list as "all 58 are wide open."

For each route below: add `dependencies=[Depends(require_permission("..."))]`
(or `require_attribute(...)` for a role-attribute check), or confirm it's
genuinely meant to be public and add it to
`AuthenticationMiddleware.PUBLIC_ROUTES` instead. Once this list is empty,
wire `assert_all_routes_have_permission_declarations()` into `app.main`'s
startup event per `route_security_audit.py`'s docstring — that's the actual
HRMS-0114 "fails to start if any route lacks a declaration" behavior.
