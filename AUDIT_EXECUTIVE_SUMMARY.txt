============================== REDUNDANCY SUMMARY =============================

The core problem: DUPLICATE WORK PATHS

Current (WRONG):
  1. Create candidate in DB (multiple commits)
  2. Separately queue candidate_created message
  → Data in TWO places (DB and queue), not atomic

Correct (SHOULD BE):
  1. Create candidate + queue message in ONE transaction
  2. Single commit (all or nothing)
  → Data in ONE logical place, atomic operation

Why it matters:
- If DB succeeds but queue fails: candidate exists but no notification
- If both succeed separately: complex synchronization needed
- If one fails: can't easily rollback both
